# Идея foundation models для временных рядов

## Большая мечта

Foundation models — это попытка сделать для временных рядов то, что [GPT](https://openai.com/research/gpt-4) сделал для текста: создать одну модель, которая «понимает» домен настолько глубоко, что может решать новые задачи без дополнительного обучения. Вы загружаете предобученную модель, подаёте на вход свой ряд — и получаете прогноз. Никакого обучения на ваших данных, никакой настройки гиперпараметров, никакого feature engineering.

Это радикально отличается от традиционного подхода, где для каждой задачи нужно: собрать данные, выбрать архитектуру, подобрать гиперпараметры, обучить модель, провалидировать, итерировать. Foundation model обещает пропустить всё это и сразу получить работающий прогноз.

Звучит как магия. И как у всякой магии, здесь есть тонкости, ограничения и случаи, когда магия не работает. Эта часть книги посвящена тому, чтобы разобраться, когда foundation models действительно полезны, а когда лучше использовать традиционные подходы.

## Почему это сложнее, чем для текста

[GPT](https://openai.com/research/gpt-4) работает, потому что текст имеет универсальную структуру. Слово «кошка» означает примерно одно и то же в любом тексте — научной статье, романе, твите. Грамматика английского языка одинакова везде. Модель, выучившая эти универсалии на миллиардах текстов, может применять их к новым текстам.

Временные ряды устроены иначе. Значение 42.7 само по себе не означает ничего. Это может быть температура, цена акции, количество заказов, нагрузка на сервер. Масштабы разные, паттерны разные, даже понятие «сезонности» разное — суточная, недельная, годовая, или вообще отсутствует.

Есть несколько фундаментальных проблем, которые foundation models для временных рядов должны решить.

### Проблема масштаба и нормализации

Ряд продаж магазина может иметь значения от 0 до 10 000. Температура — от -30 до +40. Цена биткоина — от 0 до 100 000. Как модель должна обрабатывать такое разнообразие?

Решения варьируются:

- **Instance normalization** — нормализовать каждый ряд на его статистики (среднее, std) перед подачей в модель
- **Quantization** — превратить значения в дискретные токены (как Chronos)
- **Relative encoding** — работать с изменениями, а не абсолютными значениями

Каждый подход имеет свои trade-offs, и разные foundation models выбирают разные стратегии.

### Проблема частоты дискретизации

Минутные данные, часовые, дневные, месячные — это принципиально разные режимы. Паттерн «рост утром» имеет смысл для часовых данных, но не для месячных. Модель должна либо быть инвариантной к частоте (как FlowState), либо как-то кодировать информацию о частоте, либо обучаться на данных всех частот и надеяться на обобщение.

### Проблема контекста и горизонта

В NLP контекст — это предыдущие токены, и модель учится предсказывать следующий токен. Горизонт фиксирован: один токен. Для временных рядов горизонт варьируется: иногда нужен прогноз на час вперёд, иногда на месяц. Контекст тоже варьируется: иногда доступна история за год, иногда — за неделю.

Foundation models решают это по-разному: некоторые фиксируют максимальный контекст и горизонт, некоторые используют авторегрессионную генерацию (как DeepAR), некоторые — патчинг с переменным количеством патчей.

### Проблема доменной специфики

Ряд продаж и ряд температуры ведут себя по-разному не случайно, а потому что генерируются разными процессами. Продажи реагируют на промо и праздники. Температура следует физическим законам. Может ли одна модель выучить оба типа паттернов?

Практика показывает, что может — до определённой степени. Foundation models учатся распознавать общие паттерны (тренд, сезонность, автокорреляция), которые встречаются в разных доменах. Но domain-specific модели (как Toto для observability) иногда показывают лучшие результаты на своём домене.

## Три режима использования

Foundation models можно использовать в трёх режимах, которые отличаются по соотношению «усилия / качество».

### Zero-shot

Модель используется как есть, без какого-либо обучения на ваших данных. Вы подаёте историю — получаете прогноз.

**Плюсы:**

- Мгновенный результат, никакого обучения
- Работает для cold start (новые ряды без истории)
- Не нужен GPU для обучения (только для инференса, и то не всегда)

**Минусы:**

- Качество может быть ниже, чем у модели, обученной на ваших данных
- Модель не знает специфику вашего домена
- Нет возможности использовать ковариаты (в большинстве случаев)

**Когда использовать:**

- Быстрый baseline
- Cold start сценарии
- Когда нет ресурсов на обучение
- Когда рядов много и они разнородные

### Fine-tuning

Модель дообучается на ваших данных. Предобученные веса используются как инициализация, затем модель адаптируется к вашему домену.

**Плюсы:**

- Лучшее качество, чем zero-shot
- Модель адаптируется к специфике ваших данных
- Быстрее, чем обучение с нуля (меньше эпох)

**Минусы:**

- Нужны вычислительные ресурсы для обучения
- Риск переобучения на маленьких данных
- Сложнее в поддержке (нужно переобучать при изменении данных)

**Когда использовать:**

- Есть достаточно данных для дообучения
- Zero-shot даёт неудовлетворительное качество
- Домен сильно отличается от данных предобучения

### Feature extraction

Модель используется как encoder для извлечения представлений (embeddings) из временных рядов. Эти представления затем используются в другой модели — например, в простом линейном слое для прогнозирования или в классификаторе.

**Плюсы:**

- Универсальные представления для разных задач
- Можно комбинировать с другими признаками
- Быстрое дообучение «головы»

**Минусы:**

- Сложнее пайплайн
- Не все foundation models поддерживают этот режим
- Качество зависит от того, насколько хороши представления

**Когда использовать:**

- Задачи помимо прогнозирования (классификация, anomaly detection)
- Нужно комбинировать временные ряды с другими данными
- Transfer learning между задачами

## Таксономия архитектур

Foundation models для временных рядов можно классифицировать по нескольким осям.

### По способу токенизации

**Point-based.** Каждая точка ряда — отдельный токен. Простейший подход, но приводит к очень длинным последовательностям и бессмысленному сравнению отдельных чисел.

**Patch-based.** Группы точек (патчи) становятся токенами. [PatchTST](https://arxiv.org/abs/2211.14730), [TimesFM](https://arxiv.org/abs/2310.10688), [Moirai](https://arxiv.org/abs/2402.02592) используют этот подход. Снижает длину последовательности, создаёт более информативные токены.

**Quantization-based.** Значения квантуются в дискретные токены, как слова в тексте. [Chronos](https://arxiv.org/abs/2403.07815) использует этот подход, буквально превращая прогнозирование в языковую задачу.

### По архитектуре backbone

**Encoder-only.** Модель строит представление входа, которое затем декодируется в прогноз простым слоем. [PatchTST](https://arxiv.org/abs/2211.14730), [Moirai](https://arxiv.org/abs/2402.02592).

**Decoder-only.** Модель авторегрессионно генерирует прогноз токен за токеном. [TimesFM](https://arxiv.org/abs/2310.10688), [Lag-Llama](https://arxiv.org/abs/2310.08278), [TimeGPT](https://docs.nixtla.io/).

**Encoder-decoder.** Классическая seq2seq архитектура. [Chronos](https://arxiv.org/abs/2403.07815) (на базе T5).

### По типу выхода

**Point forecast.** Одно значение на каждый шаг горизонта. Проще, но не даёт информации о неопределённости.

**Probabilistic forecast.** Распределение или квантили. [Chronos](https://arxiv.org/abs/2403.07815) (сэмплы), [TiRex](https://arxiv.org/abs/2402.02868) (квантили), [Lag-Llama](https://arxiv.org/abs/2310.08278) (параметры распределения).

### По открытости

**Полностью открытые.** Веса, код, данные обучения доступны. Chronos, Lag-Llama, Moirai.

**Частично открытые.** Веса доступны, но детали обучения или данные — нет. TimesFM.

**Закрытые.** Только API. TimeGPT.

## Бенчмарки и реальность

Как оценивать foundation models? Существует несколько основных бенчмарков.

### GIFT-Eval

Наиболее комплексный бенчмарк на момент 2025 года. Включает 144 датасета из разных доменов, разных частот, разных горизонтов. Оценивает zero-shot качество по MASE, SMAPE и другим метрикам.

Лидеры на момент написания (2025): FlowState, TiRex, Moirai, Chronos. Актуальный лидерборд доступен на [HuggingFace](https://huggingface.co/spaces/Salesforce/GIFT-Eval).

### Chronos-ZS

Бенчмарк от Amazon, фокусирующийся на zero-shot прогнозировании. Включает классические датасеты (M-competitions, Monash).

### LSF (Long Sequence Forecasting)

Бенчмарк на длинных горизонтах: ETT, Electricity, Weather, Traffic. Здесь трансформерные модели традиционно показывают хорошие результаты.

### Важные оговорки

**Бенчмарк ≠ реальность.** Модель, лидирующая на GIFT-Eval, может плохо работать на вашем конкретном домене. Бенчмарки тестируют усреднённое качество на разнородных данных, а вам важно качество на ваших данных.

**Leakage.** Некоторые foundation models обучены на данных, пересекающихся с тестовыми датасетами бенчмарков. Это делает сравнение нечестным. Авторы стараются избегать leakage, но полностью исключить его сложно.

**Вычислительные ресурсы.** Большая модель может показывать лучшее качество, но требовать GPU для инференса. Маленькая модель хуже по метрикам, но работает на CPU. Что лучше — зависит от вашего сценария.

## Что мы будем рассматривать

В следующих постах мы разберём шесть foundation models, представляющих разные подходы и trade-offs.

**[Chronos](https://arxiv.org/abs/2403.07815) (Amazon)** — квантизация значений в токены, T5-архитектура, вероятностный выход через сэмплирование. Радикальный подход «временной ряд как текст».

**[TimeGPT](https://docs.nixtla.io/) (Nixtla)** — закрытая модель с API-first подходом. Пример коммерческого foundation model. Мы обсудим, когда такой подход имеет смысл.

**[TimesFM](https://arxiv.org/abs/2310.10688) (Google)** — открытая модель с патчингом и decoder-архитектурой. Обучена на Google Trends и публичных данных.

**[Moirai](https://arxiv.org/abs/2402.02592) (Salesforce)** — any-variate архитектура с mixture of experts. Поддерживает ряды с любым количеством переменных.

**[Lag-Llama](https://arxiv.org/abs/2310.08278)** — полностью открытая модель (веса, код, данные). Decoder-only с вероятностным выходом через распределения.

**[Toto](https://www.datadoghq.com/blog/ai-forecasting/) (Datadog)** — domain-specific foundation model для observability. Пример того, как специализация может побеждать универсальность.

Для каждой модели мы разберём архитектуру, сильные и слабые стороны, и покажем код для использования.

## Как выбирать foundation model

Перед тем как погружаться в детали каждой модели, вот высокоуровневая схема выбора:

```
Нужен ли zero-shot?
├─ Нет → рассмотрите N-HiTS, DeepAR (обучение на своих данных)
└─ Да ↓

Важна ли открытость?
├─ Да → Chronos, Moirai, Lag-Llama, TimesFM
└─ Нет (API OK) → TimeGPT тоже вариант

Какой домен?
├─ Observability / метрики → Toto
└─ Общий / разнородный ↓

Нужен ли вероятностный выход?
├─ Да → Chronos, Lag-Llama, TiRex, FlowState
└─ Нет → TimesFM, Moirai (point forecast режим)

Какие вычислительные ресурсы?
├─ Только CPU → Chronos-Tiny, TimeGPT API
├─ Consumer GPU (8-16GB) → большинство моделей
└─ Enterprise GPU → большие версии Chronos, Moirai
```

Это упрощённая схема. В реальности нужно экспериментировать: взять несколько моделей, прогнать на ваших данных, сравнить метрики. Foundation models достаточно просты в использовании, чтобы такое сравнение заняло часы, а не недели.
