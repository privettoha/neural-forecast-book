## N-BEATS

# N-BEATS: когда MLP достаточно

## Ключевая идея

N-BEATS[^nbeats] — это архитектура, которая в 2020 году показала: для прогнозирования временных рядов не нужны ни рекуррентные связи, ни механизм внимания. Обычные полносвязные слои, организованные правильным образом, способны побеждать LSTM и трансформеры на стандартных бенчмарках M3 и M4[^m4]. Секрет не в сложности вычислительных блоков, а в том, как модель декомпозирует задачу прогнозирования на последовательность более простых подзадач.

Название расшифровывается как **N**eural **B**asis **E**xpansion **A**nalysis for Interpretable **T**ime **S**eries forecasting — нейронный анализ разложения по базису для интерпретируемого прогнозирования. За громоздким названием скрывается элегантная идея: вместо того чтобы напрямую предсказывать будущие значения, модель учится представлять и прогноз, и реконструкцию прошлого как линейные комбинации базисных функций.

**Результаты на M4:** На момент публикации N-BEATS показал улучшение на 3% по sMAPE над ES-RNN (победителем M4) и на 11% над чистыми статистическими методами[^nbeats]. Это был первый случай, когда «чистая» нейросеть без специфических компонентов временных рядов (ARIMA-like блоки, экспоненциальное сглаживание) победила на крупном бенчмарке.

**Почему не M5?** На соревновании M5 (2020) N-BEATS не стал лидером. Причина: M5 — это ритейл-данные Walmart, где критически важны ковариаты (цены, промо-акции, праздники). Базовый N-BEATS работает только с историей целевой переменной и не умеет использовать внешние признаки. Это ограничение привело к созданию N-BEATSx[^nbeatsx] и объясняет, почему для задач с ковариатами нужны другие архитектуры (TFT, DeepAR).

## Анатомия архитектуры

N-BEATS состоит из трёх уровней иерархии: блоки (blocks) объединяются в стеки (stacks), стеки — в модель.

```
┌─────────────────────────────────────────────────────────────────┐
│                         N-BEATS Model                           │
│  ┌─────────────┐   ┌─────────────┐         ┌─────────────┐     │
│  │   Stack 1   │ → │   Stack 2   │ → ... → │   Stack M   │     │
│  │  (trend)    │   │(seasonality)│         │  (generic)  │     │
│  └─────────────┘   └─────────────┘         └─────────────┘     │
│         ↓                 ↓                       ↓             │
│    partial y₁        partial y₂             partial yₘ         │
│         └─────────────────┴───────────────────────┘             │
│                           ↓                                     │
│                    Final forecast: Σ yᵢ                         │
└─────────────────────────────────────────────────────────────────┘
```

### Блок: базовая единица вычислений

Минимальная единица N-BEATS — это блок. На вход блок получает вектор исторических значений $\mathbf{x} \in \mathbb{R}^L$, на выход выдаёт две вещи: **backcast** $\hat{\mathbf{x}} \in \mathbb{R}^L$ (реконструкцию входа) и **forecast** $\hat{\mathbf{y}} \in \mathbb{R}^H$ (частичный прогноз).

Внутри блока:

1. Входной вектор проходит через стек из 4 полносвязных слоёв с ReLU:

$$\mathbf{h} = \text{FC}_4 \circ \text{ReLU} \circ \text{FC}_3 \circ \text{ReLU} \circ \text{FC}_2 \circ \text{ReLU} \circ \text{FC}_1(\mathbf{x})$$

2. Два отдельных линейных слоя генерируют коэффициенты разложения:

$$\boldsymbol{\theta}^b = \text{Linear}^b(\mathbf{h}), \quad \boldsymbol{\theta}^f = \text{Linear}^f(\mathbf{h})$$

**Бутылочное горлышко:** Размерность $\boldsymbol{\theta}$ намеренно мала (обычно 8-32 для interpretable, чуть больше для generic). Это информационное узкое место заставляет модель сжимать всю информацию о сигнале в несколько коэффициентов базисных функций. Низкая размерность $\boldsymbol{\theta}$ работает как мощный регуляризатор — модель вынуждена учить только самые важные паттерны, отбрасывая шум.

3. Коэффициенты умножаются на матрицы базисных функций:

$$\hat{\mathbf{x}} = \mathbf{V}^b \boldsymbol{\theta}^b, \quad \hat{\mathbf{y}} = \mathbf{V}^f \boldsymbol{\theta}^f$$

где $\mathbf{V}^b \in \mathbb{R}^{L \times \dim(\boldsymbol{\theta}^b)}$ и $\mathbf{V}^f \in \mathbb{R}^{H \times \dim(\boldsymbol{\theta}^f)}$ — матрицы базисных функций.

```
┌──────────────────────────────────────────────────────────┐
│                        Block                              │
│                                                          │
│  x ──→ [FC₁→ReLU→FC₂→ReLU→FC₃→ReLU→FC₄] ──→ h           │
│                                              │            │
│                              ┌───────────────┼────────┐  │
│                              ↓               ↓        │  │
│                         Linear^b        Linear^f      │  │
│                              ↓               ↓        │  │
│                             θ^b             θ^f       │  │
│                              ↓               ↓        │  │
│                           V^b·θ^b        V^f·θ^f      │  │
│                              ↓               ↓        │  │
│                          backcast       forecast      │  │
└──────────────────────────────────────────────────────────┘
```

### Зачем нужен backcast?

Backcast — ключевой элемент архитектуры, а не побочный продукт. Идея в том, что каждый блок пытается «объяснить» часть входного сигнала. То, что блок понял и смог реконструировать, **вычитается** из входа перед передачей следующему блоку:

$$\mathbf{x}_{\ell+1} = \mathbf{x}_\ell - \hat{\mathbf{x}}_\ell$$

Следующий блок работает уже с остатком — тем, что предыдущий блок не смог объяснить.

**Визуализация doubly residual stacking:**

```
Вход x₁ = [исходный ряд]
     │
     ▼
┌─────────┐
│ Block 1 │──→ ŷ₁ (partial forecast) ────────────────┐
└────┬────┘                                          │
     │ x̂₁ (backcast)                                 │
     ▼                                               │
x₂ = x₁ - x̂₁  [остаток: что Block 1 не объяснил]    │
     │                                               │
     ▼                                               │
┌─────────┐                                          │
│ Block 2 │──→ ŷ₂ (partial forecast) ────────────┐  │
└────┬────┘                                      │  │
     │ x̂₂ (backcast)                             │  │
     ▼                                           │  │
x₃ = x₂ - x̂₂  [остаток: что Block 1+2 не объяснили] │  │
     │                                           │  │
     ▼                                           │  │
    ...                                          │  │
     │                                           │  │
     ▼                                           ▼  ▼
xₗ ≈ 0  [в идеале всё объяснено]        ŷ = ŷ₁ + ŷ₂ + ... + ŷₗ
```

Это **doubly residual stacking** — название из оригинальной статьи[^nbeats]. Механизм похож на градиентный бустинг: каждое следующее дерево учится на ошибках предыдущих. Только здесь вместо деревьев — нейросетевые блоки, а вместо ошибок предсказания — остатки после реконструкции.

### Стек: группа блоков с общим базисом

Блоки объединяются в стеки. Внутри одного стека все блоки используют одинаковый тип базисных функций $\mathbf{V}^b$, $\mathbf{V}^f$. Между стеками передаётся остаток от backcast, а частичные прогнозы всех блоков суммируются:

$$\hat{\mathbf{y}} = \sum_{\ell=1}^{L} \hat{\mathbf{y}}_\ell$$

где $L$ — общее количество блоков во всех стеках.

## Два режима: generic и interpretable

N-BEATS существует в двух конфигурациях, которые отличаются выбором базисных функций.

### Generic (универсальная)

Базисные функции — это просто **обучаемые параметры**. Матрицы $\mathbf{V}^b$ и $\mathbf{V}^f$ инициализируются случайно и обучаются вместе с остальными весами модели.

```python
# Generic: базис — обучаемые параметры
V_b = nn.Parameter(torch.randn(lookback, theta_b_dim))
V_f = nn.Parameter(torch.randn(horizon, theta_f_dim))
```

Никаких ограничений, максимальная гибкость. Но никакой интерпретируемости — нельзя сказать, что именно выучил каждый стек.

**Типичная конфигурация:** 30 стеков по 1 блоку, 512 нейронов в скрытых слоях.

### Interpretable (интерпретируемая)

Базисные функции **фиксированы** и имеют понятный смысл. Это не просто «возможность» получить тренд и сезонность — это **архитектурное ограничение**. Модель принудительно ограничена этими функциями и физически не может выучить ничего, кроме полиномов и гармоник.

**Стек тренда** использует полиномиальный базис:

$$V^{\text{trend}} = \begin{bmatrix} 1 \\ t \\ t^2 \\ \vdots \\ t^p \end{bmatrix}^T$$

где $t \in [0, 1]$ — нормализованное время, $p$ — степень полинома (обычно 2-3).

**Стек сезонности** использует гармонический (Фурье) базис:

$$V^{\text{seasonality}} = \begin{bmatrix} \cos(2\pi t) & \sin(2\pi t) & \cos(4\pi t) & \sin(4\pi t) & \cdots \end{bmatrix}$$

```python
# Interpretable: trend basis (полиномы)
t = torch.linspace(0, 1, horizon)
V_trend = torch.stack([t**i for i in range(poly_degree + 1)], dim=1)

# Interpretable: seasonality basis (гармоники)
t = torch.linspace(0, 1, horizon)
harmonics = []
for k in range(1, n_harmonics + 1):
    harmonics.extend([torch.cos(2*np.pi*k*t), torch.sin(2*np.pi*k*t)])
V_season = torch.stack(harmonics, dim=1)
```

**Типичная конфигурация:** 2 стека (trend + seasonality), по 3 блока в каждом.

В интерпретируемой конфигурации можно буквально извлечь из модели оценку тренда и сезонности — это полезно для валидации модели и объяснения прогнозов бизнес-заказчикам.

## Почему это работает

### Иерархическая декомпозиция

Вместо того чтобы решать сложную задачу прогнозирования целиком, модель разбивает её на последовательность простых подзадач. Каждый блок отвечает за объяснение части сигнала. Это снижает нагрузку на каждый отдельный блок и делает обучение более стабильным.

### Residual connections с семантикой

В отличие от стандартных skip connections в ResNet, где остаток просто складывается с выходом, в N-BEATS остаток имеет явный смысл: это то, что предыдущие блоки не смогли объяснить. Модель буквально учится на своих ошибках в процессе forward pass.

### Двойной выход как регуляризация

Необходимость генерировать и backcast, и forecast заставляет скрытое представление $\mathbf{h}$ быть информативным в обе стороны. Это неявная форма регуляризации, которая улучшает обобщающую способность[^nbeats].

### Отсутствие рекуррентности

Все блоки работают независимо после получения своего входа. Это позволяет полностью параллелизировать вычисления и избежать проблем с затуханием градиентов.

## Сильные стороны

**Простота реализации.** Архитектура состоит из стандартных компонентов — FC слои, ReLU, линейные проекции. Нет сложных механизмов внимания, нет скрытых состояний.

**Интерпретируемость.** В interpretable режиме можно декомпозировать прогноз на тренд и сезонность — для валидации и объяснения стейкхолдерам.

**Хорошая работа на средних горизонтах.** N-BEATS показывает сильные результаты на горизонтах от нескольких дней до нескольких недель[^m4].

**Эффективность на данных с чистой структурой.** Если в ряде есть выраженный тренд и сезонность без сложных нелинейных взаимодействий, N-BEATS ловит эти паттерны очень хорошо.

## Ограничения

**Фиксированный горизонт.** N-BEATS обучается на конкретный горизонт $H$. Нужен другой горизонт — переобучайте модель. Это следствие encoder-only архитектуры (глава 10).

**Отсутствие нативной поддержки ковариат.** Базовая архитектура работает только с историей целевой переменной. N-BEATSx[^nbeatsx] добавляет эту возможность, но это уже модификация.

**Вычислительная стоимость на длинных горизонтах.** Каждый блок генерирует полный вектор прогнозов размера $H$. При $H=168$ (неделя почасовых данных) и 30 блоках это 5040 выходов на forward pass. N-HiTS[^nhits] решает эту проблему через иерархическую интерполяцию (глава 12).

**Чувствительность к гиперпараметрам.** Количество блоков, слоёв, размер скрытого слоя, тип базиса — всё влияет на качество. На практике приходится подбирать конфигурацию под конкретный датасет.

## Гиперпараметры: что настраивать

| Параметр | Типичные значения | Влияние |
|----------|-------------------|---------|
| `input_size` | 2H — 7H | См. примечание ниже |
| `n_blocks` | 1-3 на стек | Больше → выше ёмкость, риск переобучения |
| `mlp_units` | [256, 256] — [512, 512] | Больше → выше ёмкость |
| `stack_types` | generic / trend+seasonality | Зависит от интерпретируемости |
| `n_polynomials` | 2-3 | Только для interpretable |
| `n_harmonics` | 1-3 | Только для interpretable |

**⚠️ Критически важно: `input_size` (lookback window)**

N-BEATS очень чувствителен к длине входного окна:

- **Слишком маленькое окно** (< 2H): модель не увидит сезонность. Если у вас недельная сезонность и H=7, окно в 7 точек захватит только один период — модель не сможет выучить паттерн.

- **Слишком большое окно** (> 7H): FC-слои начнут переобучаться на шуме из далёкого прошлого. Помните: первый FC-слой имеет `input_size × hidden_dim` параметров — при большом окне это миллионы весов.

- **Практическое правило:** Окно должно содержать 2-3 полных периода основной сезонности. Для дневных данных с недельной сезонностью: `input_size = 14-21`.

**Рекомендация из статьи[^nbeats]:** Для generic — 30 стеков по 1 блоку, 512 нейронов. Для interpretable — 2 стека по 3 блока.

## Когда выбирать N-BEATS

✅ **Используйте N-BEATS, если:**
- Достаточно данных для глобальной модели (сотни рядов или длинная история)
- Горизонт прогноза фиксирован и известен заранее
- Важна интерпретируемость (trend/seasonality decomposition)
- Нет критичных экзогенных переменных

❌ **Рассмотрите альтернативы, если:**
- Горизонт переменный → foundation models (Chronos, TimesFM)
- Много ковариат → TFT, DeepAR, N-BEATSx
- Очень длинные горизонты (>100 точек) → N-HiTS (глава 12)
- Мало данных → foundation models с zero-shot

## Выводы

1. **N-BEATS показал:** для SOTA не нужны RNN или attention — достаточно правильно организованных MLP.

2. **Ключевая идея:** doubly residual stacking — каждый блок объясняет часть сигнала, остаток передаётся дальше.

3. **Два режима:** generic (максимальная гибкость) и interpretable (декомпозиция на тренд + сезонность).

4. **Главное ограничение:** фиксированный горизонт и отсутствие ковариат в базовой версии.

5. **Наследие:** N-BEATS заложил фундамент для N-HiTS, TSMixer и других MLP-based архитектур.

В следующей главе рассмотрим N-HiTS — эволюцию N-BEATS, которая решает проблему вычислительной сложности на длинных горизонтах через иерархическую интерполяцию.
