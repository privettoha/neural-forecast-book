# Датасеты и методология

## Зачем фиксировать данные и правила

Сравнивать модели корректно — сложнее, чем кажется. Легко получить результат, который выглядит впечатляюще, но рассыпается при ближайшем рассмотрении: модель случайно подсмотрела будущее через неправильный split, метрика посчитана на подмножестве рядов, где модель работает лучше всего, или горизонт прогноза выбран так, чтобы скрыть накопление ошибки.

В этой главе мы фиксируем правила игры: какие данные используем, как их разбиваем, какие метрики считаем и с чем сравниваем. Это позволит читателю воспроизвести эксперименты и критически оценить результаты.

## Основной датасет: Store Sales

**Store Sales — Kaggle Competition** — наш основной датасет для экспериментов[^storesales].

### Описание данных

Продажи в эквадорских магазинах сети Corporación Favorita. Данные охватывают период с 2013 по 2017 год.

| Характеристика | Значение |
|----------------|----------|
| Количество рядов | ~1,800 (комбинации магазин × категория) |
| Гранулярность | Ежедневная |
| Длина истории | ~4.5 года (~1,700 точек на ряд) |
| Горизонт прогноза | 16 дней |
| Целевая переменная | Продажи (sales) |

### Структура данных

```
train.csv
├── date         — дата
├── store_nbr    — ID магазина (54 магазина)
├── family       — категория товаров (33 категории)
├── sales        — продажи (целевая переменная)
└── onpromotion  — количество товаров на промо

stores.csv
├── store_nbr    — ID магазина
├── city         — город
├── state        — штат
├── type         — тип магазина (A, B, C, D, E)
└── cluster      — кластер магазина

oil.csv
└── dcoilwtico   — цена нефти (Эквадор — нефтедобывающая страна)

holidays_events.csv
├── date         — дата праздника
├── type         — тип (Holiday, Event, Transfer, Bridge)
├── locale       — уровень (National, Regional, Local)
└── description  — описание
```

### Почему Store Sales

**Богатая структура.** Множество рядов с общими паттернами — идеально для cross-learning. Недельная и годовая сезонность, влияние праздников, промо-эффекты.

**Реалистичность.** Это реальные данные из ритейла, типичная задача demand forecasting. Если модель не работает здесь — она не будет работать в production.

**Доступность ковариат.** Праздники, промо, цена нефти, метаданные магазинов — можно тестировать модели с экзогенными переменными.

**Известный бенчмарк.** Kaggle competition с public leaderboard — можно сравнить свои результаты с тысячами других решений.

### Особенности данных

**Нули и пропуски.** Некоторые комбинации магазин×категория имеют нулевые продажи (магазин не продаёт эту категорию). Это не пропуски — это истинные нули.

**Праздники Эквадора.** Сложная структура праздников: национальные, региональные, локальные. Некоторые праздники переносятся (transferred), создавая «мосты» (bridge days).

**Землетрясение 2016.** 16 апреля 2016 года произошло сильное землетрясение. Это структурный разрыв в данных, который нужно учитывать.

## Вторичный датасет: ETT (Electricity Transformer Temperature)

ETT — стандартный бенчмарк для long-term forecasting в академических статьях[^informer].

### Описание данных

Данные с трансформаторов электросети в Китае. Две станции (ETTh1, ETTh2 — hourly; ETTm1, ETTm2 — 15-минутные).

| Характеристика | ETTh | ETTm |
|----------------|------|------|
| Гранулярность | Hourly | 15 минут |
| Длина | ~17,500 точек | ~70,000 точек |
| Переменные | 7 | 7 |
| Период | 2 года | 2 года |

### Переменные

- **OT (Oil Temperature)** — целевая переменная, температура масла трансформатора
- **HUFL, HULL, MUFL, MULL, LUFL, LULL** — нагрузки на разных уровнях

### Почему ETT

**Академический стандарт.** Используется в Informer, Autoformer, FEDformer, PatchTST, iTransformer — можно напрямую сравнивать с результатами из статей.

**Long-term forecasting.** Стандартные горизонты: 96, 192, 336, 720 шагов. Это позволяет тестировать способность моделей к долгосрочному прогнозированию.

**Multivariate.** 7 переменных с корреляциями — можно тестировать channel-dependent vs channel-independent подходы.

### Ограничения ETT

**Один домен.** Только энергетика. Результаты могут не переноситься на другие области.

**Синтетичность задачи.** Прогноз температуры масла на 720 часов (30 дней) вперёд — сомнительная практическая ценность.

**Известные проблемы бенчмаркинга.** Drop Last trick и другие артефакты (см. главу 05).

## Методология экспериментов

### Разбиение данных

Мы используем **временной split** без перемешивания. Это критически важно: случайное разбиение (random shuffle) создаёт data leakage, когда модель «видит» будущее при обучении.

**Правильно — временной split:**
```
Время →
2013 ──────────────────────────────────────────────── 2017
|←————————————— Train ———————————————→|←— Val —→|←— Test —→|
                                       │         │
                                   cutoff_1   cutoff_2

✓ Модель обучается ТОЛЬКО на прошлом
✓ Валидация и тест — строго в будущем относительно train
✓ Соответствует реальному production-сценарию
```

**Неправильно — случайный split:**
```
2013 ──────────────────────────────────────────────── 2017
  █ Train  ░ Val  ▓ Test  (перемешаны случайно)
  █░█▓█░▓█░█▓░█▓█░▓█░█▓█░▓░█▓█░▓█░

✗ Модель видит данные из 2017 при обучении
✗ Тестируется на данных из 2014, которые «окружены» train
✗ Метрики завышены, модель не работает в production
```

**Для Store Sales:**
- Train: до 2017-07-15
- Validation: 2017-07-16 — 2017-07-31 (16 дней)
- Test: 2017-08-01 — 2017-08-15 (16 дней, соответствует competition)

**Для ETT:**
- Стандартное разбиение 60/20/20 по времени
- Или разбиение из оригинальных статей для сравнимости

**Важно:** Никакого случайного разбиения, никакой кросс-валидации по строкам. Только честное разделение по времени, как в реальном production.

### Бейзлайны

Каждую нейросеть мы сравниваем с простыми моделями:

| Бейзлайн | Описание | Когда силён |
|----------|----------|-------------|
| **Seasonal Naive** | $\hat{y}_{t+h} = y_{t+h-s}$, где s — период | Выраженная сезонность |
| **Naive** | $\hat{y}_{t+h} = y_t$ (последнее значение) | Random walk данные |
| **Drift** | Линейная экстраполяция | Сильный тренд |
| **AutoETS** | Автоматический выбор ETS модели | Univariate с трендом/сезонностью |
| **AutoARIMA** | Автоматический выбор ARIMA | Univariate, стационарные ряды |

**Правило:** Если нейросеть не побеждает Seasonal Naive, она не демонстрирует практического преимущества — независимо от вычислительных затрат.

### Метрики

#### Основная метрика Store Sales: RMSLE

**RMSLE (Root Mean Squared Logarithmic Error):**
$$RMSLE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(\log(\hat{y}_i + 1) - \log(y_i + 1))^2}$$

Это официальная метрика соревнования Store Sales, и выбор неслучаен. В ритейле ошибка на товаре с продажами 100→110 должна штрафоваться так же, как на товаре с продажами 10→11 (обе ошибки — 10%). Без логарифмирования модель будет «забивать» на low-volume товары и оптимизировать только high-volume, что бесполезно для бизнеса.

**Почему +1 в формуле:** Защита от $\log(0)$. При нулевых продажах $\log(0+1) = 0$.

#### Общие метрики

**MAE (Mean Absolute Error):**
$$MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$

Интерпретируемая метрика в единицах данных. Менее чувствительна к выбросам, чем MSE.

**MSE (Mean Squared Error):**
$$MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

Стандарт в deep learning. Штрафует большие ошибки сильнее.

**MASE (Mean Absolute Scaled Error):**
$$MASE = \frac{MAE_{model}}{MAE_{naive}}$$

Масштабирует ошибку относительно Seasonal Naive. MASE < 1 означает, что модель лучше наивного прогноза.

#### Проблема нулей: WAPE вместо MAPE

**MAPE** (Mean Absolute Percentage Error) не работает с нулями — деление на ноль в знаменателе. Для данных с zero-inflation (как Store Sales) используйте **WAPE**:

**WAPE (Weighted Absolute Percentage Error):**
$$WAPE = \frac{\sum_{i=1}^{n}|y_i - \hat{y}_i|}{\sum_{i=1}^{n}|y_i|}$$

WAPE эквивалентен MAE, нормированному на сумму actuals. Нули в числителе не создают проблем, а ряды с нулевыми продажами просто не вносят вклад в знаменатель.

| Метрика | Проблема с нулями | Альтернатива |
|---------|-------------------|--------------|
| MAPE | Деление на 0 | WAPE, sMAPE |
| MASE | Деление на 0 в naive | Исключить константные ряды |
| RMSLE | Нет (log(0+1)=0) | — |

#### Для probabilistic прогнозов

**CRPS (Continuous Ranked Probability Score):**
$$CRPS = \int_{-\infty}^{\infty} (F(x) - \mathbf{1}(x \geq y))^2 dx$$

Обобщение MAE на распределения. Меньше — лучше.

**Coverage:**
$$Coverage_{\alpha} = \frac{1}{n}\sum_{i=1}^{n}\mathbf{1}(y_i \in [q_{\alpha/2}, q_{1-\alpha/2}])$$

Доля наблюдений, попавших в интервал. Для 90% интервала должно быть ~0.9.

## Практические рекомендации

### Для воспроизведения экспериментов книги

```python
# Загрузка Store Sales
from datasetsforecast.datasets import StoreSalesDataset
df = StoreSalesDataset.load()

# Загрузка ETT
from datasetsforecast.datasets import ETTDataset
df_etth1 = ETTDataset.load('ETTh1')
```

### Для собственных экспериментов

1. **Начните с бейзлайнов.** Seasonal Naive занимает 1 минуту. Если ваши данные не имеют сезонности, Naive — ваш baseline.

2. **Используйте MASE.** Это позволяет сравнивать результаты между разными датасетами.

3. **Фиксируйте seed.** Нейросети недетерминированы. Один прогон ничего не значит.

4. **Тестируйте на своих данных.** Результаты на ETT могут не переноситься на ваш домен.

## Выводы

- **Store Sales** — основной датасет для практических экспериментов (ритейл, ковариаты, cross-learning)
- **ETT** — для сравнения с академическими результатами (long-term forecasting)
- **Временной split** без перемешивания — единственный честный способ (random shuffle = data leakage)
- **Seasonal Naive** — минимальный baseline, который нужно побить
- **RMSLE** — для Store Sales (учитывает относительную ошибку, важно для ритейла)
- **WAPE** — альтернатива MAPE для данных с нулями
- **MASE** — для сравнения между датасетами
