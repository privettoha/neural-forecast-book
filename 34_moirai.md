# Moirai: any-variate foundation model

## Ключевая идея

Moirai[^moirai] — foundation model от Salesforce (2024), которая решает проблему **multivariate forecasting** в zero-shot режиме. В отличие от Chronos и TimesFM, которые работают с одной переменной, Moirai принимает **любое число каналов** (any-variate) и прогнозирует все одновременно.

Ключевая инновация — **универсальная архитектура**, которая работает с рядами разной размерности без переобучения. Модель, обученная на данных с 7 каналами, может прогнозировать данные с 321 каналом.

**Результаты:** Moirai показывает state-of-the-art zero-shot результаты на multivariate бенчмарках и конкурирует с task-specific моделями (iTransformer, PatchTST) без обучения на целевых данных[^moirai].

## Проблема multivariate

Большинство foundation models работают с **univariate** рядами:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    UNIVARIATE vs MULTIVARIATE                           │
│                                                                         │
│  UNIVARIATE (Chronos, TimesFM):                                        │
│  ─────────────────────────────────                                      │
│  Вход: [x₁, x₂, ..., xₗ]  (одна переменная)                           │
│  Выход: [ŷ₁, ŷ₂, ..., ŷₕ]                                             │
│                                                                         │
│  Для multivariate: обрабатываем каждый канал отдельно                  │
│  Проблема: не моделируем корреляции между каналами                     │
│                                                                         │
│  ═══════════════════════════════════════════════════════════════════   │
│                                                                         │
│  MULTIVARIATE (Moirai):                                                │
│  ────────────────────────                                               │
│  Вход: X ∈ ℝ^(L×C)  (L точек, C каналов)                               │
│  Выход: Ŷ ∈ ℝ^(H×C)                                                   │
│                                                                         │
│  Все каналы обрабатываются вместе                                      │
│  Моделируем корреляции между переменными                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Почему это сложно для foundation models

**Проблема:** Число каналов $C$ варьируется от датасета к датасету.

- ETTh1: 7 каналов
- Electricity: 321 канал
- Traffic: 862 канала

Как обучить одну модель, которая работает со всеми?

## Any-variate подход

Moirai использует **any-variate** архитектуру:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        ANY-VARIATE АРХИТЕКТУРА                          │
│                                                                         │
│  Идея: каждый канал = отдельный токен                                  │
│                                                                         │
│  Вход: X ∈ ℝ^(L×C)                                                     │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. PER-VARIATE PATCHING                                        │   │
│  │                                                                  │   │
│  │  Канал 1: [x₁¹...x₁ᴾ] [x₁ᴾ⁺¹...x₁²ᴾ] ...  →  N патчей         │   │
│  │  Канал 2: [x₂¹...x₂ᴾ] [x₂ᴾ⁺¹...x₂²ᴾ] ...  →  N патчей         │   │
│  │  ...                                                             │   │
│  │  Канал C: [xᶜ¹...xᶜᴾ] [xᶜᴾ⁺¹...xᶜ²ᴾ] ...  →  N патчей         │   │
│  │                                                                  │   │
│  │  Итого: C × N патчей                                            │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  2. PATCH EMBEDDING + VARIATE ID                                │   │
│  │                                                                  │   │
│  │  Каждому патчу добавляется:                                     │   │
│  │  • Patch embedding (как в PatchTST)                             │   │
│  │  • Variate ID embedding (какой это канал)                       │   │
│  │  • Time embedding (какой это момент времени)                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  3. MASKED ENCODER TRANSFORMER                                  │   │
│  │                                                                  │   │
│  │  Self-attention между ВСЕМИ патчами всех каналов               │   │
│  │  Attention matrix: (C × N) × (C × N)                           │   │
│  │                                                                  │   │
│  │  Модель учит:                                                   │   │
│  │  • Временные зависимости (между патчами одного канала)         │   │
│  │  • Межканальные зависимости (между каналами)                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  4. DISTRIBUTION HEAD                                           │   │
│  │                                                                  │   │
│  │  Для каждого патча прогноза:                                   │   │
│  │  embedding → (μ, σ) параметры распределения                    │   │
│  │                                                                  │   │
│  │  Поддерживаемые распределения:                                 │   │
│  │  • Student's t (для данных с выбросами)                        │   │
│  │  • Log-normal (для положительных данных)                       │   │
│  │  • Negative Binomial (для счётных данных)                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Выход: Ŷ ∈ ℝ^(H×C) + uncertainty                                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Multiple Patch Sizes

Moirai использует **несколько размеров патчей** для разных частот:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    MULTIPLE PATCH SIZES                                 │
│                                                                         │
│  Частота        Размер патча    Пример                                 │
│  ─────────────────────────────────────────────────                      │
│  Минуты         8              8 минут = 1 патч                        │
│  Часы           16             16 часов = 1 патч                       │
│  Дни            32             32 дня = 1 патч                         │
│  Недели/Месяцы  64             64 точки = 1 патч                       │
│                                                                         │
│  Модель автоматически выбирает размер на основе freq                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## Masked Encoder Pre-training

Moirai использует **masked pre-training** (как BERT):

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    MASKED PRE-TRAINING                                  │
│                                                                         │
│  1. Берём ряд с C каналами и L точками                                 │
│  2. Разбиваем на патчи: C × N патчей                                   │
│  3. Маскируем часть патчей (например, последние 30%)                   │
│  4. Обучаем модель восстанавливать замаскированные патчи               │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Канал 1: [P₁] [P₂] [P₃] [MASK] [MASK]                         │   │
│  │  Канал 2: [P₁] [P₂] [P₃] [MASK] [MASK]                         │   │
│  │  Канал 3: [P₁] [P₂] [P₃] [MASK] [MASK]                         │   │
│  │                                                                  │   │
│  │  Задача: восстановить [MASK] патчи                             │   │
│  │                                                                  │   │
│  │  Loss = NLL предсказанного распределения                       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Это эквивалентно forecasting: маскируем будущее, учимся предсказывать │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Базовый пример

```python
import torch
from uni2ts.model.moirai import MoiraiForecast, MoiraiModule

# Загрузка модели
model = MoiraiForecast.load_from_checkpoint(
    "Salesforce/moirai-1.0-R-base",
    prediction_length=24,
    context_length=512,
    patch_size=32,
    num_samples=100
)

# Подготовка данных
# context: [batch, channels, time]
context = torch.randn(1, 7, 512)  # 7 каналов, 512 точек

# Прогноз
forecast = model(context)
# forecast.shape: [batch, num_samples, channels, prediction_length]

# Медиана и квантили
median = forecast.median(dim=1)
p10 = forecast.quantile(0.1, dim=1)
p90 = forecast.quantile(0.9, dim=1)
```

## Сравнение с другими foundation models

| Аспект | Moirai | Chronos | TimesFM | Lag-Llama |
|--------|--------|---------|---------|-----------|
| **Multivariate** | ✓ Native | ✗ | ✗ | ✗ |
| **Probabilistic** | ✓ | ✓ | ✗ | ✓ |
| **Архитектура** | Encoder | Enc-Dec | Decoder | Decoder |
| **Распределения** | 3 типа | 1 тип | — | 1 тип |
| **Размеры** | 14M-311M | 8M-710M | 200M | 7M |

## Сильные стороны

**Native multivariate.** Единственная foundation model с нативной поддержкой multiple channels.

**Any-variate.** Работает с любым числом каналов без переобучения.

**Probabilistic.** Несколько типов распределений для разных данных.

**Masked pre-training.** Эффективный подход, проверенный в NLP и vision.

## Ограничения

**Вычислительная сложность.** Attention $(C \times N)^2$ — квадратичная по числу каналов и патчей. Для 1000+ каналов нужно много памяти.

**Encoder-only.** Фиксированный горизонт, как у N-BEATS.

**Меньший масштаб.** 311M параметров — меньше, чем Chronos-Large (710M).

## Когда выбирать Moirai

✅ **Используйте Moirai, если:**
- Multivariate данные с важными корреляциями между каналами
- Нужен zero-shot на multivariate
- Нужен probabilistic output
- Число каналов варьируется

❌ **Рассмотрите альтернативы, если:**
- Univariate данные → Chronos, TimesFM (проще)
- Очень много каналов (>500) + длинный контекст → может не хватить памяти
- Нужны ковариаты → TimeGPT

## Выводы

1. **Any-variate** — ключевая инновация. Одна модель для любого числа каналов.

2. **Masked pre-training** эффективно переносится из NLP во временные ряды.

3. **Multivariate zero-shot** — уникальная возможность. Другие foundation models требуют обработки каналов по отдельности.

4. **Practical choice** для multivariate задач с переменным числом каналов.

5. **Trade-off:** Универсальность vs вычислительная сложность.

В следующей главе рассмотрим **Lag-Llama** — probabilistic foundation model с акцентом на лаговые признаки.
