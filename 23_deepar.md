## Ключевая идея

DeepAR — это модель, которая в 2017 году изменила представление о том, как нейросети могут прогнозировать временные ряды. До DeepAR глубокое обучение для рядов означало «обучить LSTM на одном ряде и надеяться на лучшее». DeepAR предложил три идеи, которые стали стандартом для последующих архитектур: глобальная модель на множестве рядов, авторегрессионная генерация прогноза и вероятностный выход вместо точечного.

Название происходит от Deep AutoRegressive — глубокая авторегрессионная модель. Авторегрессия здесь означает, что модель генерирует прогноз последовательно: предсказывает следующий шаг, использует это предсказание как вход для следующего, и так далее до конца горизонта.

Хотя с 2017 года появились более продвинутые архитектуры, DeepAR остаётся важной точкой отсчёта. Модель до сих пор используется в продакшене (Amazon SageMaker, GluonTS), а её идеи — вероятностный выход, ковариаты, глобальное обучение — перекочевали практически во все современные подходы.

## Контекст: что было до DeepAR

Чтобы оценить вклад DeepAR, нужно понимать ландшафт 2017 года.

**Классические методы** — ARIMA, ETS, Prophet — работали с каждым рядом независимо. Если у вас 10 000 товаров, вы обучаете 10 000 моделей. Это не масштабируется: для новых товаров без истории модели нет, для товаров с короткой историей модель переобучается, поддерживать зоопарк из тысяч моделей — операционный кошмар.

**Ранние нейросети** — vanilla LSTM и GRU — пытались решить задачу прогнозирования как seq2seq: вход — история, выход — будущее. Но их обычно обучали на отдельных рядах (локальный подход), и они выдавали точечный прогноз без оценки неопределённости.

**Проблема cold start** — новый товар, новый магазин, новый сервис — не имеет истории для обучения модели. Классические методы здесь бессильны.

DeepAR решил все три проблемы одним архитектурным выбором.

## Глобальная модель: учимся на всех рядах сразу

Центральная идея DeepAR — обучить одну RNN на всех доступных временных рядах. Модель не запоминает конкретные ряды, а учится распознавать паттерны: как выглядит сезонный пик, как ведёт себя тренд, как ряд реагирует на праздники.

Во время обучения модель видит случайные окна из случайных рядов. Каждое окно состоит из двух частей: context (история, которую модель видит) и prediction (будущее, которое модель должна предсказать). Модель учится на разнообразии — рядах с разной длиной, разным масштабом, разной сезонностью.

Во время инференса модель получает историю нового ряда — возможно, такого, которого не было в обучении — и генерирует прогноз, опираясь на выученные паттерны.

Это принципиально отличается от локального подхода. Если ряд A имеет богатую историю с чёткой сезонностью, а ряд B — новый товар с двумя неделями данных, глобальная модель может перенести знание о сезонности с A на B. Локальная модель для B просто не будет знать о сезонности — ей не на чем учиться.

## Авторегрессионная генерация

DeepAR генерирует прогноз шаг за шагом, а не весь горизонт сразу. На каждом шаге модель:

1. Получает на вход предыдущее значение (во время обучения — истинное, во время инференса — сгенерированное)
2. Обновляет скрытое состояние RNN
3. Выдаёт параметры распределения для следующего значения
4. Сэмплирует из этого распределения (или берёт среднее для точечного прогноза)

Формально, для момента времени $t$:

$$h_t = \text{RNN}(h_{t-1}, [y_{t-1}, x_t])$$
$$\theta_t = \text{Linear}(h_t)$$
$$y_t \sim p(y | \theta_t)$$

где $h_t$ — скрытое состояние RNN, $y_{t-1}$ — предыдущее значение ряда, $x_t$ — ковариаты (признаки) для момента $t$, $\theta_t$ — параметры выходного распределения.

Авторегрессия имеет важное следствие: ошибки накапливаются. Если модель ошиблась на первом шаге прогноза, эта ошибка влияет на все последующие шаги. Это делает DeepAR менее стабильным на длинных горизонтах по сравнению с direct-подходами (N-BEATS, N-HiTS), которые генерируют весь горизонт сразу.

## Вероятностный выход

Вместо точечного прогноза «продажи завтра = 150» DeepAR выдаёт распределение: «продажи завтра распределены с параметрами μ=150, σ=20». Из этого распределения можно получить:

- Точечный прогноз (среднее или медиана)
- Доверительные интервалы (квантили)
- Полное распределение для оценки рисков

DeepAR поддерживает несколько семейств распределений:

**Gaussian (нормальное)** — для непрерывных данных с симметричным шумом. Параметры: μ (среднее), σ (стандартное отклонение).

**Negative Binomial** — для count data (количество заказов, число событий). Параметры: μ (среднее), α (параметр дисперсии). Поддерживает overdispersion — когда дисперсия больше среднего.

**Student-t** — для данных с тяжёлыми хвостами (выбросами). Параметры: μ, σ, ν (степени свободы).

Выбор распределения — это гиперпараметр модели. Для ритейла с целочисленными продажами обычно используют Negative Binomial. Для непрерывных метрик — Gaussian или Student-t.

Функция потерь — negative log-likelihood выбранного распределения:

$$\mathcal{L} = -\sum_{t} \log p(y_t | \theta_t)$$

Модель учится выдавать такие параметры распределения, чтобы истинные значения были наиболее вероятны.

## Ковариаты: внешняя информация

DeepAR умеет использовать дополнительные признаки, что отличает его от многих современных архитектур (N-BEATS в базовой версии ковариаты не поддерживает).

**Статические признаки (static features)** — характеристики ряда, которые не меняются во времени: категория товара, регион магазина, тип клиента. Кодируются через embedding и конкатенируются к входу RNN на каждом шаге.

**Динамические признаки (dynamic features)** — признаки, которые меняются во времени: день недели, месяц, праздник, цена, промо-флаг. Подаются на вход RNN вместе с предыдущим значением ряда.

Важное требование: динамические признаки должны быть известны на горизонте прогноза. День недели известен заранее, цена может быть запланирована, но фактическая погода на следующую неделю — нет. DeepAR не умеет работать с признаками, которые сами нужно прогнозировать.

## Архитектура в деталях

```
Входы на каждом шаге t:
- y_{t-1}: предыдущее значение (или 0 для первого шага)
- x_t: динамические ковариаты
- e: embedding статических признаков

    ↓
Конкатенация: [y_{t-1}, x_t, e]
    ↓
LSTM (несколько слоёв)
    ↓
Скрытое состояние h_t
    ↓
Linear → параметры распределения θ_t
    ↓
Sampling (во время инференса) или Loss (во время обучения)
```

**Масштабирование входов.** Временные ряды имеют разный масштаб — один ряд в единицах, другой в миллионах. DeepAR нормализует каждый ряд на его среднее значение в context window. Это позволяет модели работать с относительными изменениями, а не абсолютными величинами.

**Lagged features.** Помимо $y_{t-1}$, DeepAR может использовать значения с большим лагом: $y_{t-7}$ (неделю назад), $y_{t-30}$ (месяц назад). Это помогает модели видеть сезонные паттерны даже если RNN «забыла» далёкое прошлое.

## Обучение и инференс

**Обучение.** Для каждого ряда случайно выбирается окно: context + prediction. Модель прогоняется через context (teacher forcing — используются истинные значения), затем через prediction (тоже teacher forcing). Loss считается только на prediction части.

**Инференс.** Модель прогоняется через context с истинными значениями. Затем переходит в режим генерации: сэмплирует из предсказанного распределения, использует сэмпл как вход для следующего шага. Процесс повторяется несколько раз (например, 100 сэмплов), и из множества траекторий строятся квантили.

**Monte Carlo sampling.** Поскольку на каждом шаге происходит сэмплирование, разные прогоны дают разные траектории. Это и есть способ получения вероятностного прогноза: 100 траекторий дают эмпирическое распределение, из которого можно взять любой квантиль.

## Сильные стороны

**Вероятностный выход из коробки.** Не нужно отдельно обучать модель для квантилей или строить conformal prediction поверх точечного прогноза. Распределение — это нативный выход модели.

**Работа с ковариатами.** Праздники, промо, цены — всё это можно подать на вход и получить условный прогноз. «Какие продажи при скидке 20%?» — DeepAR может ответить.

**Гибкость горизонта.** Авторегрессионная генерация позволяет делать прогноз на любой горизонт без переобучения модели. Одна и та же модель может прогнозировать на 7 дней и на 30 дней.

**Холодный старт.** Новый ряд с минимальной историей получает разумный прогноз, потому что модель опирается на выученные паттерны, а не на конкретную историю этого ряда.

## Ограничения

**Накопление ошибки.** Авторегрессия означает, что ошибка на шаге 1 влияет на шаг 2, ошибка на шаге 2 — на шаг 3, и так далее. На длинных горизонтах прогноз может «уплыть» далеко от реальности.

**Скорость инференса.** Генерация происходит последовательно — нельзя распараллелить по времени. Плюс Monte Carlo sampling требует многократных прогонов. Это медленнее, чем direct-подходы.

**Чувствительность к гиперпараметрам.** Количество слоёв, размер скрытого состояния, выбор распределения, лаги — всё это влияет на качество и требует подбора.

**Возраст архитектуры.** LSTM — это 1997 год. С тех пор появились более эффективные последовательные архитектуры (xLSTM, SSM), которые решают проблемы классических RNN.

## Код: DeepAR с GluonTS

DeepAR реализован в библиотеке GluonTS от Amazon. Это оригинальная реализация от авторов модели.

python

```python
import pandas as pd
import numpy as np
from gluonts.dataset.pandas import PandasDataset
from gluonts.torch.model.deepar import DeepAREstimator
from gluonts.torch.distributions import NegativeBinomialOutput, StudentTOutput

# Подготовка данных
# GluonTS ожидает данные в определённом формате
train_df = pd.read_csv('train.csv')
train_df['ds'] = pd.to_datetime(train_df['ds'])

# Создаём dataset
dataset = PandasDataset.from_long_dataframe(
    train_df,
    item_id='unique_id',
    timestamp='ds',
    target='y',
    freq='D'
)

# Конфигурация DeepAR
estimator = DeepAREstimator(
    freq='D',
    prediction_length=16,
    context_length=64,                    # длина контекста
    
    # Архитектура
    num_layers=2,                         # количество LSTM слоёв
    hidden_size=40,                       # размер скрытого состояния
    dropout_rate=0.1,
    
    # Распределение выхода
    distr_output=NegativeBinomialOutput(),  # для count data
    # distr_output=StudentTOutput(),        # для данных с выбросами
    
    # Лаги для сезонности
    lags_seq=[1, 7, 14, 21, 28],          # вчера, неделю назад, ...
    
    # Обучение
    lr=1e-3,
    batch_size=32,
    num_batches_per_epoch=100,
    trainer_kwargs={'max_epochs': 50}
)

# Обучаем
predictor = estimator.train(dataset)

# Прогнозируем
from gluonts.evaluation import make_evaluation_predictions

forecast_it, ts_it = make_evaluation_predictions(
    dataset=dataset,
    predictor=predictor,
    num_samples=100  # Monte Carlo samples
)

forecasts = list(forecast_it)
tss = list(ts_it)

# Доступ к результатам
for forecast in forecasts[:3]:
    print(f"Item: {forecast.item_id}")
    print(f"  Mean: {forecast.mean[:5]}")           # точечный прогноз
    print(f"  Median: {forecast.median[:5]}")       # медиана
    print(f"  P10: {forecast.quantile(0.1)[:5]}")   # 10-й перцентиль
    print(f"  P90: {forecast.quantile(0.9)[:5]}")   # 90-й перцентиль
```

### Визуализация вероятностного прогноза

python

```python
import matplotlib.pyplot as plt

def plot_probabilistic_forecast(ts, forecast, title=''):
    """
    Визуализация истории и вероятностного прогноза.
    """
    fig, ax = plt.subplots(figsize=(12, 4))
    
    # История
    history = ts[-100:].to_timestamp()
    ax.plot(history.index, history.values, color='black', label='История')
    
    # Прогноз
    forecast_index = pd.date_range(
        start=history.index[-1] + pd.Timedelta(days=1),
        periods=len(forecast.mean),
        freq='D'
    )
    
    # Медиана
    ax.plot(forecast_index, forecast.median, color='blue', label='Медиана')
    
    # Интервалы
    ax.fill_between(
        forecast_index,
        forecast.quantile(0.1),
        forecast.quantile(0.9),
        alpha=0.3,
        color='blue',
        label='80% интервал'
    )
    
    ax.fill_between(
        forecast_index,
        forecast.quantile(0.25),
        forecast.quantile(0.75),
        alpha=0.5,
        color='blue',
        label='50% интервал'
    )
    
    ax.legend()
    ax.set_title(title)
    plt.tight_layout()
    plt.show()

# Визуализируем первый прогноз
plot_probabilistic_forecast(tss[0], forecasts[0], title=f'Прогноз для {forecasts[0].item_id}')
```

## DeepAR vs современные модели

|Критерий|DeepAR|N-HiTS|Foundation models|
|---|---|---|---|
|Вероятностный выход|✓ Нативно|~ Через quantile loss|✓ Большинство|
|Ковариаты|✓ Статические + динамические|~ Только N-BEATSx|~ Зависит от модели|
|Длинные горизонты|✗ Накопление ошибки|✓ Direct подход|✓ Direct подход|
|Скорость инференса|✗ Последовательно|✓ Параллельно|✓ Параллельно|
|Cold start|✓ Глобальная модель|✓ Глобальная модель|✓✓ Zero-shot|
|Зрелость|✓ 7+ лет в продакшене|✓ 3+ года|~ 1-2 года|

**Когда использовать DeepAR:**

- Нужен вероятностный прогноз с ковариатами
- Есть динамические признаки, известные на горизонте прогноза
- Горизонт прогноза относительно короткий (до 30 шагов)
- Важна зрелость и поддержка (Amazon SageMaker)

**Когда искать альтернативы:**

- Длинные горизонты (>50 шагов)
- Важна скорость инференса
- Нужен zero-shot для новых доменов

## Что дальше

DeepAR показал, что RNN могут работать для временных рядов при правильном подходе: глобальное обучение, вероятностный выход, ковариаты. Но классические LSTM имеют известные ограничения: затухание градиентов, сложность параллелизации, ограниченная память.

В следующих постах мы рассмотрим, как современные последовательные архитектуры решают эти проблемы. TiRex использует xLSTM — расширенную версию LSTM с экспоненциальными гейтами и матричной памятью. FlowState строится на State Space Models, которые сочетают преимущества RNN и свёрточных сетей. Оба показывают state-of-the-art результаты в 2025 году, доказывая, что последовательные архитектуры рано списывать со счетов.
