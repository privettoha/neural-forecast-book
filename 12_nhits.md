## N-HiTS

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/privettoha/neural-forecast-book/blob/main/notebooks/12_nhits.ipynb)

N-HiTS (Neural Hierarchical Interpolation for Time Series) — развитие N-BEATS, которое решает его главную проблему: неэффективность на длинных горизонтах. Если N-BEATS пытается предсказать каждую точку будущего напрямую, то N-HiTS делает это через иерархическую декомпозицию по частотам. Результат — ускорение в 25–50 раз на длинных горизонтах при лучшем качестве[^nhits].

[^nhits]: Challu, C., et al. "N-HiTS: Neural Hierarchical Interpolation for Time Series Forecasting." AAAI 2023. Table 3. https://arxiv.org/abs/2201.12886

### Идея

Ключевое отличие от N-BEATS — **multi-rate processing**.

Временной ряд содержит паттерны разных масштабов (долгосрочные тренды, недельная сезонность, внутридневные колебания). N-HiTS обрабатывает каждый масштаб отдельным стеком, подавая на вход данные с разной степенью агрегации. Вместо того чтобы предсказывать каждую точку горизонта, модель предсказывает коэффициенты $\theta$, которые через basis expansion превращаются в прогноз, а затем интерполируются до нужной размерности.

Это снижает параметризацию и делает прогноз на длинных горизонтах стабильнее.

### Архитектура

Модель состоит из нескольких стеков (обычно 3–5), где каждый специализируется на своём временном масштабе.

**🔢 Multi-rate input sampling**

Каждый стек получает входные данные с разной агрегацией через MaxPooling:

➖ Первый стек: максимально агрегированные данные (например, по 8 точкам) → захватывает долгосрочный тренд
➖ Средние стеки: умеренная агрегация (по 4 точки) → недельная/месячная сезонность
➖ Последний стек: исходные данные → высокочастотные детали

Это аналог wavelet-декомпозиции, но обучаемый end-to-end. MaxPooling работает лучше AveragePooling — улучшение MAE доходит до 15%[^nhits-pooling].

[^nhits-pooling]: Challu, C., et al. "N-HiTS." AAAI 2023. Appendix A.4.2. https://arxiv.org/abs/2201.12886

**🔢 Блоки с basis expansion**

Внутри каждого стека — стандартные MLP-блоки с ReLU. Блок предсказывает коэффициенты $\theta^b$ и $\theta^f$, которые через линейные слои создают два выхода:

➖ **Backcast** (из $\theta^b$)
➖ **Forecast** (из $\theta^f$)

**🔢 Hierarchical interpolation**

Ключевая идея экономии параметров: forecast интерполируется до полного горизонта H, а backcast остаётся как есть для residual stacking. Линейная интерполяция работает лучше nearest neighbor и cubic[^nhits-interp].

[^nhits-interp]: Challu, C., et al. "N-HiTS." AAAI 2023. Section 3.2. https://arxiv.org/abs/2201.12886

**🔢 Residual forecasting**

Как и в N-BEATS — doubly residual stacking:

➖ Backcast вычитается из входа → следующий блок получает остаток
➖ Forecast суммируется для финального прогноза

Каждый стек специализируется на своём частотном диапазоне без конфликта между трендом и шумом.

**🔢 Порядок стеков имеет значение**

Эмпирически показано[^nhits-order], что лучшая конфигурация — начинать с низкочастотных компонентов:

[^nhits-order]: Challu, C., et al. "N-HiTS." AAAI 2023. Appendix A.4.3. https://arxiv.org/abs/2201.12886

| Стек | Pooling kernel | Expressiveness ratio | Что ловит |
|------|----------------|---------------------|-----------|
| 1 | 8 | 4–8 | Тренд |
| 2 | 4 | 2–4 | Сезонность |
| 3 | 1 | 1 | Детали и шум |

Обратный порядок даёт худшие результаты: MAE хуже на 4.6%, MSE на 7.5%.

### Экономия на вычислениях

Пример: горизонт 168 часов (неделя), три стека.

**N-BEATS:** каждый стек генерирует 168 значений → $3 \times 168 = 504$

**N-HiTS** с expressiveness ratios 1/24, 1/12, 1:
➖ Стек 1: $\lceil 168/24 \rceil = 7$ значений
➖ Стек 2: $\lceil 168/12 \rceil = 14$ значений
➖ Стек 3: 168 значений
➖ Итого: $7 + 14 + 168 = 189$ значений

Учитывая сжатие входов, ускорение на практике — 25–50x.

### Что умеет

➖ Длинные горизонты: эффективен на 100+ точек (где N-BEATS уже не справляется)
➖ Автоматическая декомпозиция: не нужно вручную выделять тренд/сезонность
➖ Экономия параметров: компактнее Transformer-моделей
➖ Интерпретируемость: можно визуализировать вклад каждого стека (аналог STL, но обучаемый)

### Ограничения

➖ Дополнительные гиперпараметры: kernel sizes и expressiveness ratios для каждого стека
➖ Требует знания масштабов: для данных с нерегулярными паттернами выбор неочевиден
➖ Линейная интерполяция может «размазать» резкие скачки
➖ Требует несколько тысяч наблюдений для обучения
➖ Не учитывает нерегулярность рядов (пропуски, разная частота)

### Когда использовать

**Да:**
➖ Длинные горизонты (14–90 дней для daily, 24–168 часов для hourly)
➖ Данные с иерархической структурой (тренд + недельная + дневная сезонность)
➖ Нужна интерпретируемость через частотную декомпозицию
➖ Ограниченные вычислительные ресурсы

**Нет:**
➖ Короткие горизонты (<30 точек) → N-BEATS достаточно
➖ Много ковариат → TFT
➖ Cold start → foundation models

### N-HiTS vs N-BEATS

| Критерий | N-BEATS | N-HiTS |
|----------|---------|--------|
| Короткий горизонт (<30) | ✓ | ✓ |
| Длинный горизонт (>100) | ✗ Медленно | ✓ |
| Многомасштабная структура | ~ Может выучить | ✓ Явно моделирует |
| Простота настройки | ✓ | ~ Нужно подбирать масштабы |

**Практическое правило:** начинайте с N-HiTS, если горизонт >30 точек или есть многомасштабная структура. Для простых задач N-BEATS проще.
