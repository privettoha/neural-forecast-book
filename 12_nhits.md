[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/privettoha/neural-forecast-book/blob/main/notebooks/12_nhits.ipynb)

## Ключевая идея

N-HiTS — это эволюция N-BEATS, которая решает две практические проблемы предшественника: избыточные вычисления на длинных горизонтах и неспособность явно моделировать паттерны разных временных масштабов. Если N-BEATS заставляет каждый блок генерировать прогноз для каждой точки горизонта, то N-HiTS позволяет разным блокам работать с разной гранулярностью — один блок отвечает за долгосрочный тренд и делает редкие прогнозы, другой ловит краткосрочные колебания и делает частые.

Название расшифровывается как Neural Hierarchical Interpolation for Time Series forecasting — нейронная иерархическая интерполяция для прогнозирования временных рядов. Ключевое слово здесь — интерполяция: блоки, работающие на грубом масштабе, делают мало прогнозов, а промежуточные значения восстанавливаются через интерполяцию.

Результат — модель, которая в 25–50 раз быстрее N-BEATS на длинных горизонтах и при этом показывает лучшее качество за счёт явного разделения низкочастотных и высокочастотных компонент сигнала.

## Проблема N-BEATS на длинных горизонтах

Чтобы понять мотивацию N-HiTS, посчитаем, сколько параметров генерирует N-BEATS. Допустим, у нас горизонт 168 точек (неделя почасовых данных), 3 стека по 3 блока, и каждый блок должен выдать и backcast длины 336 (два горизонта), и forecast длины 168.

Каждый из 9 блоков генерирует $(336 + 168) = 504$ значения. Итого $9 \times 504 = 4536$ выходов на один forward pass. При этом большинство блоков решают, по сути, одну и ту же задачу на одном и том же масштабе — это избыточно.

Хуже того, когда все блоки работают на одинаковой гранулярности, модели сложно разделить медленные тренды и быстрые осцилляции. Блок может «застрять» между попыткой уловить недельную сезонность и суточные колебания, не делая хорошо ни то, ни другое.

## Две идеи N-HiTS

N-HiTS вводит два механизма, которые работают в связке: multi-rate input processing (многочастотная обработка входов) и hierarchical interpolation (иерархическая интерполяция выходов).

### Multi-rate input processing

В N-BEATS каждый блок получает на вход одно и то же окно исторических данных в исходном разрешении. N-HiTS добавляет перед каждым стеком слой MaxPool, который агрегирует входные данные с разным шагом.

Первый стек может получать данные как есть — каждый час. Второй стек получает данные, агрегированные по 12 часов (максимум из каждых 12 точек). Третий стек — по 24 часа. Это как если бы разные стеки «смотрели» на ряд с разным зумом: один видит детали, другой — общую картину.

Формально, если $x$ — входной вектор длины $L$, то стек с kernel size $k$ получает:

$$x^{(k)} = \text{MaxPool1D}(x, \text{kernel\_size}=k)$$

Длина входа для этого стека становится $\lfloor L/k \rfloor$.

Почему MaxPool, а не Average? Авторы экспериментировали с обоими вариантами и обнаружили, что MaxPool лучше сохраняет информативные пики — важные события вроде промо-дней или аномалий не «размазываются» усреднением.

### Hierarchical interpolation

Вторая идея — симметричная первой, но для выходов. Если стек работает на грубом масштабе, ему не нужно генерировать прогноз для каждой точки горизонта. Достаточно сгенерировать меньше точек и восстановить промежуточные значения интерполяцией.

Допустим, горизонт 168 часов. Стек, отвечающий за долгосрочный тренд, может генерировать только 7 значений (по одному на день), а внутридневные детали восстановятся линейной интерполяцией. Стек, ловящий суточные колебания, генерирует 14 значений (по два на день). И только стек для мелких флуктуаций работает на полном разрешении.

Это называется expressiveness ratio — отношение длины выхода блока к полному горизонту. Стек с expressiveness ratio 1/24 генерирует в 24 раза меньше точек, чем горизонт.

Математически, блок генерирует «сжатый» прогноз $\hat{y}^{(k)}$ длины $\lceil H/k \rceil$, который затем интерполируется до полной длины $H$:

$$\hat{y} = \text{Interpolate}(\hat{y}^{(k)}, \text{size}=H)$$

В реализации используется линейная интерполяция — простая, быстрая, достаточно гладкая для большинства временных рядов.

## Как это работает вместе

Представим N-HiTS с тремя стеками для прогноза на неделю вперёд (168 часов).

**Стек 1: низкочастотный.** Kernel size 24 для входа, expressiveness ratio 1/24 для выхода. Этот стек «видит» дневные агрегаты истории и генерирует 7 точек прогноза — по одной на день. Его задача — уловить медленный тренд: растут продажи к концу недели или падают?

**Стек 2: среднечастотный.** Kernel size 12, expressiveness ratio 1/12. Стек видит 12-часовые агрегаты и генерирует 14 точек. Его задача — различить утро и вечер, будни и выходные.

**Стек 3: высокочастотный.** Kernel size 1 (без агрегации), expressiveness ratio 1. Стек работает на полном разрешении и ловит часовые колебания — пики в обеденное время, провалы ночью.

Финальный прогноз — сумма интерполированных выходов всех стеков:

$$\hat{y} = \sum_{s=1}^{S} \text{Interpolate}(\hat{y}^{(s)})$$

Backcast работает аналогично: каждый стек реконструирует историю на своём масштабе, остаток передаётся следующему стеку.

## Expressiveness ratio: интуиция

Термин «expressiveness ratio» может звучать абстрактно, но за ним стоит простая идея. Представьте, что вы рисуете прогноз от руки. Для долгосрочного тренда достаточно поставить несколько точек и соединить линией — промежуточные значения очевидны. Для краткосрочных колебаний нужно рисовать каждую точку, иначе потеряете детали.

Expressiveness ratio — это именно эта идея, переведённая на язык нейросетей. Низкий ratio (1/24) означает «рисуй грубо, детали не важны». Высокий ratio (1) означает «рисуй точно, каждая точка имеет значение».

Важно, что разные масштабы не мешают друг другу. Низкочастотный стек не пытается угадать, какой будет продажа в 3 часа ночи в среду — это не его работа. Он отвечает за общий уровень среды по сравнению с четвергом. Детали дорисует высокочастотный стек.

## Экономия на вычислениях

Посчитаем выигрыш на примере. Горизонт 168, три стека. В N-BEATS каждый из трёх стеков генерирует 168 значений прогноза — итого $3 \times 168 = 504$.

В N-HiTS с expressiveness ratios 1/24, 1/12, 1:

- Стек 1: $\lceil 168/24 \rceil = 7$ значений
- Стек 2: $\lceil 168/12 \rceil = 14$ значений
- Стек 3: $168$ значений
- Итого: $7 + 14 + 168 = 189$ значений

Экономия скромная, но это только forecast. Учтите, что входы тоже сжимаются, и количество параметров в полносвязных слоях пропорционально длине входа. На практике авторы сообщают об ускорении в 25–50 раз на длинных горизонтах.

## Архитектура в деталях

Структурно N-HiTS очень похож на N-BEATS. Те же блоки с fully connected слоями, тот же механизм residual connections для backcast, та же суммация partial forecasts. Отличия локализованы в двух местах:

**Вход блока.** Перед первым блоком каждого стека добавлен MaxPool слой с настраиваемым kernel size. Это единственное изменение на входе.

**Выход блока.** Линейный слой, генерирующий forecast, выдаёт вектор меньшей размерности (в соответствии с expressiveness ratio). После него добавлен слой интерполяции, растягивающий вектор до полного горизонта.

Backcast обрабатывается симметрично: блок генерирует сжатый backcast, который интерполируется до исходной длины входа перед вычитанием.

## Сильные стороны

**Скорость на длинных горизонтах.** Главное преимущество. Если вам нужен прогноз на месяц вперёд с часовой гранулярностью (720 точек), N-BEATS будет страдать, а N-HiTS справится без проблем.

**Явное разделение масштабов.** Вместо того чтобы надеяться, что модель сама разберётся с многомасштабной структурой, N-HiTS явно выделяет разные частотные компоненты. Это похоже на идею вейвлет-декомпозиции, но в learnable варианте.

**Лучшее качество на данных с богатой структурой.** На датасетах с выраженными паттернами разных масштабов — недельная сезонность плюс суточная плюс тренд — N-HiTS стабильно обходит N-BEATS. Это не артефакт скорости, а реальное улучшение предсказательной силы.

**Совместимость с N-BEATS.** API и логика обучения практически идентичны. Если у вас есть код для N-BEATS, переход на N-HiTS — это изменение нескольких строк.

## Ограничения

**Дополнительные гиперпараметры.** К параметрам N-BEATS добавляются kernel sizes для MaxPool и expressiveness ratios для каждого стека. Выбор этих значений зависит от структуры данных: если вы укажете kernel size 24 для данных без суточной сезонности, модель будет агрегировать случайным образом.

**Предположение о масштабах.** N-HiTS работает лучше всего, когда вы заранее знаете, какие масштабы важны. Для дневных данных с недельной сезонностью очевидно: kernel sizes 1, 7, 28. Для данных с нерегулярными паттернами выбор менее очевиден.

**Линейная интерполяция.** Простая линейная интерполяция может не справляться с резкими изменениями. Если в данных есть ступенчатые переходы (например, цена изменилась скачком), интерполяция «размажет» этот скачок.

**Те же ограничения, что и у N-BEATS.** Фиксированный горизонт, отсутствие нативной поддержки ковариат в базовой версии, необходимость достаточного количества данных для обучения глобальной модели.

## Код: N-HiTS на Store Sales

python

```python
import pandas as pd
import numpy as np
from neuralforecast import NeuralForecast
from neuralforecast.models import NHITS
from neuralforecast.losses.pytorch import MAE

# Загружаем данные
train = pd.read_csv('train.csv')
train['ds'] = pd.to_datetime(train['ds'])

# Параметры
HORIZON = 16
SEASON_LENGTH = 7

# Конфигурация N-HiTS
# Три стека с разными масштабами
model = NHITS(
    h=HORIZON,
    input_size=4 * HORIZON,              # более длинное окно помогает низкочастотным стекам
    loss=MAE(),
    max_steps=1000,
    
    # Конфигурация стеков
    n_pool_kernel_size=[1, 2, 4],        # kernel sizes для MaxPool
    n_freq_downsample=[1, 2, 4],         # expressiveness ratios (обратные значения)
    stack_types=['identity'] * 3,         # тип базиса (identity — обучаемый базис без ограничений)
    n_blocks=[1, 1, 1],                   # по одному блоку в стеке
    mlp_units=[[256, 256], [256, 256], [256, 256]],
    
    scaler_type='standard',
    random_seed=42
)

# Обучаем
nf = NeuralForecast(
    models=[model],
    freq='D'
)
nf.fit(df=train)

# Прогнозируем
forecasts = nf.predict()
```

### Подбор масштабов под данные

python

```python
def suggest_pool_kernels(season_length, horizon, n_stacks=3):
    """
    Эвристика для выбора kernel sizes на основе 
    сезонности и горизонта.
    
    Идея: каждый следующий стек работает на масштабе,
    кратном предыдущему.
    """
    kernels = [1]  # первый стек всегда на полном разрешении
    
    current = 1
    for _ in range(n_stacks - 1):
        # Следующий масштаб — либо сезонность, 
        # либо удвоение предыдущего
        if current < season_length:
            next_kernel = min(season_length, current * 2)
        else:
            next_kernel = current * 2
        
        # Не превышаем горизонт
        if next_kernel > horizon:
            next_kernel = horizon
            
        kernels.append(next_kernel)
        current = next_kernel
    
    return kernels

# Для дневных данных с недельной сезонностью
kernels = suggest_pool_kernels(
    season_length=7, 
    horizon=16, 
    n_stacks=3
)
print(f"Suggested kernels: {kernels}")
# Output: Suggested kernels: [1, 2, 7]
```

## N-HiTS vs N-BEATS: когда что выбирать

|Критерий|N-BEATS|N-HiTS|
|---|---|---|
|Короткий горизонт (<30 точек)|✓ Достаточно|✓ Тоже работает|
|Длинный горизонт (>100 точек)|✗ Медленно|✓ Эффективно|
|Явная многомасштабная структура|~ Может выучить|✓ Явно моделирует|
|Простота настройки|✓ Меньше параметров|~ Нужно подбирать масштабы|
|Интерпретируемость|✓ trend/seasonality|~ Масштабы, но не компоненты|

Практическое правило: начинайте с N-HiTS, если горизонт больше 30 точек или если в данных есть очевидная многомасштабная структура (суточная + недельная сезонность, например). Для простых задач с коротким горизонтом N-BEATS может быть достаточно и проще в настройке.

## Что дальше

N-BEATS и N-HiTS показали, что MLP-архитектуры способны конкурировать с более сложными подходами. Но оба они работают только с историей целевой переменной — а что если у нас есть несколько связанных рядов или экзогенные переменные?

В следующем посте мы рассмотрим [TSMixer](https://arxiv.org/abs/2303.06053) — модель от Google, которая применяет идею «mixing» из компьютерного зрения ([MLP-Mixer](https://arxiv.org/abs/2105.01601)) к временным рядам и показывает, что простые операции перемешивания по времени и по признакам могут конкурировать с трансформерами при работе с многомерными данными.
