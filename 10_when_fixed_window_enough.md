# Когда хватит фиксированного окна

## Что такое encoder-only подход

В главе 03 мы разобрали типы архитектур: encoder-only, decoder-only, encoder-decoder. Часть 1 книги посвящена первому типу — моделям, которые принимают **фиксированное окно истории** и выдают **весь прогноз за один проход**.

$$[x_{t-L+1}, \dots, x_t] \xrightarrow{\text{Model}} [\hat{y}_{t+1}, \dots, \hat{y}_{t+H}]$$

Это самый простой и интуитивный подход к прогнозированию: модель смотрит на последние $L$ точек истории и сразу выдаёт прогноз на $H$ шагов вперёд. Никакой авторегрессии, никакого накопления ошибки, никакой итеративной генерации.

В эту категорию входят:
- **MLP-архитектуры:** N-BEATS[^nbeats], N-HiTS[^nhits], DLinear[^dlinear], TSMixer[^tsmixer]
- **Transformer encoder:** PatchTST[^patchtst], iTransformer[^itransformer]

## Преимущества фиксированного окна

### 1. Простота реализации и отладки

Encoder-only модели — это обычные нейросети прямого распространения. Вход фиксированного размера, выход фиксированного размера. Никаких циклов, никакого состояния между вызовами.

```python
# Encoder-only: один forward pass
class SimpleForecaster(nn.Module):
    def __init__(self, context_len, horizon):
        self.encoder = nn.Sequential(...)
        self.head = nn.Linear(hidden_dim, horizon)
    
    def forward(self, x):  # x: (batch, context_len)
        h = self.encoder(x)
        return self.head(h)  # (batch, horizon)
```

Сравните с авторегрессионной моделью, где нужно поддерживать состояние, обрабатывать переменную длину, управлять teacher forcing при обучении.

### 2. Скорость обучения и инференса

**Обучение:** Все примеры в batch обрабатываются параллельно. Нет зависимости между шагами горизонта — градиенты вычисляются за один backward pass.

**Инференс:** Один forward pass модели → весь прогноз готов. Для авторегрессионных моделей нужно H последовательных forward passes для горизонта H.

| Подход | Forward passes на прогноз | Параллелизация |
|--------|--------------------------|----------------|
| Encoder-only (MIMO) | 1 | Полная |
| Autoregressive | H (горизонт) | Ограничена |

На практике это даёт **10-100x ускорение инференса** для типичных горизонтов[^dlinear].

### 3. Нет накопления ошибки

Вспомним из главы 03: в авторегрессионных моделях ошибка на шаге 1 влияет на шаг 2, ошибка шага 2 — на шаг 3, и так далее. Дисперсия ошибки растёт с горизонтом.

В encoder-only прогноз на каждый шаг вычисляется напрямую из истории:

```
[история] → Encoder → Linear → [ŷ₁, ŷ₂, ŷ₃, ŷ₄, ŷ₅]
                                 ↑   ↑   ↑   ↑   ↑
                              Независимы друг от друга
```

Если $\hat{y}_1$ ошибочен, это **никак не влияет** на $\hat{y}_5$ — они вычисляются параллельно из одного и того же hidden state.

**Визуализация: рост дисперсии ошибки**

```
Дисперсия
ошибки
    │
    │                              ╱ Autoregressive
    │                           ╱    (ошибка накапливается)
    │                        ╱
    │                     ╱
    │                  ╱
    │               ╱
    │        ════════════════════  Encoder-only (MIMO)
    │                               (ошибка не накапливается)
    │
    └────────────────────────────────→ Горизонт H
         1    2    3    4    5
```

На практике это означает, что encoder-only модели сохраняют качество прогноза даже на дальних шагах горизонта, тогда как авторегрессионные модели могут значительно деградировать к концу[^dlinear].

### 4. Стабильность обучения

Encoder-only модели обучаются стабильнее:
- Нет проблемы exposure bias (модель видит при обучении то же, что при инференсе)
- Нет vanishing/exploding gradients через длинные цепочки зависимостей
- Loss напрямую отражает качество прогноза на каждом шаге

## Ограничения

### 1. Фиксированный контекст

Модель обучена на конкретную длину контекста $L$. Хотите использовать $L' \neq L$? Нужно переобучение.

```
Обучена на L=96 (4 дня часовых данных)
├── Подать L=96 → ✓ Работает
├── Подать L=192 → ✗ Размерность не совпадает
└── Подать L=48 → ✗ Нужен padding или переобучение
```

**Важный нюанс: где именно «зарыта» жёсткость?**

Для MLP причина очевидна — первый слой ожидает вектор размера $L$.

Для трансформеров (PatchTST[^patchtst], iTransformer[^itransformer]) сам механизм attention может принимать любую длину последовательности. Ограничение накладывает **линейная голова** (Flatten + Linear Head), которая ожидает вектор фиксированного размера $D \times N_{\text{patches}}$:

```
Transformer Encoder (гибкий по длине)
        ↓
  [h₁, h₂, ..., h_N]  ← N патчей, размерность D
        ↓
     Flatten
        ↓
  [h₁ ⊕ h₂ ⊕ ... ⊕ h_N]  ← вектор размера N×D
        ↓
  Linear(N×D → H)  ← ВОТ ЗДЕСЬ жёсткость!
        ↓
  [ŷ₁, ..., ŷ_H]
```

Если подать другое число патчей $N' \neq N$, размерность после Flatten не совпадёт с ожиданиями Linear Head. Это архитектурное решение, а не фундаментальное ограничение трансформеров.

**Частичное решение:** Padding нулями или средним значением. Но модель не обучалась на таких входах — качество может пострадать.

### 2. Фиксированный горизонт

Аналогично: модель обучена на горизонт H. Нужен H' > H? Варианты:
- Переобучить модель
- Использовать модель итеративно (но тогда теряем преимущество MIMO)

```
Обучена на H=24 (сутки)
├── Прогноз на 24 → ✓ Один pass
├── Прогноз на 48 → Два pass, ŷ₂₅₋₄₈ зависит от ŷ₁₋₂₄
└── Прогноз на 12 → ✓ Берём первые 12 значений
```

### 3. Нет адаптации к текущему контексту

Decoder-only модели могут адаптироваться: если после первых шагов прогноза стало понятно, что модель ошибается, следующие шаги могут скорректироваться. Encoder-only выдаёт весь прогноз сразу — коррекции нет.

### 4. Сложнее работать с ковариатами

Known future covariates (праздники, промо) требуют специальной обработки: нужно как-то подать информацию о будущих $H$ шагах в encoder, который ожидает только историю.

Решения есть (TFT[^tft], TSMixer[^tsmixer] с ковариатами), но архитектура усложняется. Типичные подходы — **конкатенация** (ковариаты добавляются к входу) или **gate-механизмы** (ковариаты модулируют скрытые представления). Оба раздувают количество параметров и усложняют обучение.

### 5. Разрыв на границах окон

Если вы прогнозируете на $H=24$ сегодня и на $H=24$ завтра, между концом первого прогноза и началом второго может возникнуть «ступенька» — разрыв непрерывности.

```
День 1: [история] → Model → [ŷ₁, ŷ₂, ..., ŷ₂₄]
                                            ↓
                                    Возможен разрыв!
                                            ↓
День 2: [новая история] → Model → [ŷ₁, ŷ₂, ..., ŷ₂₄]
```

Модель каждый раз считает прогноз заново, не зная, что она «напророчила» вчера. Авторегрессионные модели за счёт состояния или плавного перехода через собственные предсказания этой проблемы лишены.

**Практическое следствие:** Для задач, где важна непрерывность прогноза (визуализация, планирование), может потребоваться пост-обработка для сглаживания стыков.

### 6. Чувствительность к distribution shift

Encoder-only видит только «замороженный» кусок истории $L$. Модель не может адаптироваться к изменению тренда **в процессе генерации прогноза**.

```
                    Резкий разворот рынка
                           ↓
История: ────────────────┐
                         │
Прогноз encoder-only:    └──────────────→ (не знает о развороте)

Прогноз autoregressive:  └──↘            (первые шаги «чувствуют»
                              ↘───────→   разворот, корректируются)
```

Если внутри горизонта $H$ происходит структурный сдвиг, авторегрессионная модель может «почувствовать» его через собственные первые предсказания и скорректировать последующие. Encoder-only выдаёт весь прогноз сразу на основе только исторических данных.

## Когда encoder-only достаточно

### Идеальные условия

✅ **Регулярные данные с фиксированной частотой.** Часовые, дневные, недельные — любая регулярная гранулярность.

✅ **Известный горизонт планирования.** Вы всегда прогнозируете на одну и ту же глубину: неделю, месяц, квартал.

✅ **Short-to-mid term forecasting.** Горизонты от нескольких шагов до нескольких сотен. На очень длинных горизонтах (1000+ шагов) преимущества MIMO размываются.

✅ **Batch inference.** Прогнозы для множества рядов генерируются одновременно, скорость критична.

✅ **Нет или мало known future covariates.** Если ковариат много — рассмотрите TFT или DeepAR.

### Типичные задачи

| Задача | Почему encoder-only подходит |
|--------|------------------------------|
| **Demand forecasting (ритейл)** | Фиксированный горизонт (неделя/месяц), batch прогнозы для тысяч SKU |
| **Energy load forecasting** | Регулярные данные, известный горизонт (day-ahead, week-ahead) |
| **Financial metrics** | Квартальные/месячные прогнозы с фиксированным окном |
| **Capacity planning** | Прогноз нагрузки на серверы на фиксированный период |

### Красные флаги: когда смотреть в сторону decoder

🚩 **Горизонт неизвестен заранее.** Разные пользователи запрашивают разные горизонты в runtime.

🚩 **Много known future covariates.** Промо-календари, праздники, запланированные события.

🚩 **Streaming/online режим.** Прогноз должен обновляться с каждым новым наблюдением.

🚩 **Очень длинный горизонт.** 1000+ шагов, где авторегрессионная адаптация может помочь.

## Практический совет

Начинайте с encoder-only, если нет явных причин использовать decoder:

```
Ваша задача
    │
    ├── Фиксированный горизонт? ─── Да ──→ Encoder-only
    │                                         │
    │                                    N-BEATS / DLinear
    │                                    как baseline
    │
    └── Переменный горизонт? ─── Да ──→ Decoder-only
                                          │
                                     Chronos / TimesFM
                                     для zero-shot
```

Encoder-only модели проще в реализации, быстрее в обучении и инференсе, легче в отладке. Если они дают достаточное качество — усложнять архитектуру не нужно.

## Выводы

1. **Encoder-only = фиксированный вход → фиксированный выход.** Простейший и часто достаточный подход.

2. **Главные преимущества:** скорость (один forward pass), отсутствие накопления ошибки, стабильность обучения.

3. **Главные ограничения:** фиксированные $L$ и $H$, разрывы на границах окон, чувствительность к distribution shift, сложности с ковариатами.

4. **Где «зарыта» жёсткость:** В трансформерах — не в attention (он гибкий), а в Linear Head после Flatten.

5. **Идеально для:** регулярных данных, известного горизонта, batch inference, short-to-mid term forecasting.

6. **Правило:** Начинайте с encoder-only. Усложняйте только если есть конкретная причина.

В следующей главе начинаем с N-BEATS — модели, которая показала, что для SOTA не нужны ни RNN, ни трансформеры.
