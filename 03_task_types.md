# Типы задач и архитектур

## Зачем нужна эта классификация

Когда вы выбираете модель для прогнозирования, легко утонуть в разнообразии: N-BEATS, PatchTST, Chronos, DeepAR, TimesFM... Названия звучат похоже, статьи обещают SOTA, а понять, что подходит именно вашей задаче — непросто.

Эта глава даёт систему координат. Мы разберём три ключевых измерения, по которым различаются задачи и модели:

1. **Тип входа**: фиксированное окно, произвольная длина, ковариаты
2. **Архитектура**: encoder-only, decoder-only, encoder-decoder
3. **Тип выхода**: точечный прогноз, вероятностный прогноз

Плюс отдельно рассмотрим **стратегии многошагового прогнозирования** — это часто упускаемый, но критически важный выбор.

После прочтения вы сможете по описанию задачи понять, какой класс моделей рассматривать, а какой — сразу отбросить.

## Измерение 1: Тип входа

### Fixed-horizon (фиксированное окно)

Модель принимает на вход окно фиксированной длины $L$ и выдаёт прогноз на фиксированный горизонт $H$:

$$f: \mathbb{R}^L \to \mathbb{R}^H$$

Примеры: N-BEATS, N-HiTS, TSMixer, DLinear, PatchTST, iTransformer.

**Характеристики:**
- Архитектура оптимизирована под конкретные $L$ и $H$
- Изменение горизонта требует переобучения
- Простая и стабильная тренировка
- Быстрый инференс (один forward pass)

**Когда использовать:**
- Регулярные данные с фиксированной частотой
- Задачи с известным горизонтом планирования (неделя, месяц)
- Когда важна скорость инференса

### Flex-horizon (произвольная длина)

Модель может принимать контекст произвольной длины и генерировать прогноз на произвольный горизонт:

$$f: \mathbb{R}^{L_{any}} \to \mathbb{R}^{H_{any}}$$

Примеры: DeepAR, Chronos, TimesFM, Lag-Llama.

**Характеристики:**
- Авторегрессионная генерация или адаптивный контекст
- Одна модель работает с разными горизонтами
- Накопление ошибки при длинных горизонтах (для авторегрессионных)
- Медленнее на инференсе

**Когда использовать:**
- Разнородные данные с разными частотами
- Неизвестный заранее горизонт
- Zero-shot сценарии (foundation models)

**Примеры задач:**

- **Прогнозирование спроса для разных клиентов.** Ритейлер А хочет прогноз на 7 дней, ритейлер Б — на 30 дней. Одна flex-horizon модель обслуживает обоих без переобучения.

- **Операционные метрики SaaS.** Прогноз нагрузки на серверы: иногда на час вперёд (для autoscaling), иногда на месяц (для capacity planning) — разные горизонты от разных потребителей.

- **What-if сценарии в runtime.** Аналитик исследует: «Что если запустим промо через 3 дня?» Потом: «А через неделю?» Горизонт меняется интерактивно, переобучать модель на каждый запрос невозможно.

- **Ряды разной длины.** У вас 1000 временных рядов разной длины, для каждого нужен прогноз «до конца квартала» — это разное количество шагов для каждого ряда.

### With-covariates (с ковариатами)

Модель принимает не только историю целевой переменной, но и дополнительные признаки:

$$f: (\mathbb{R}^L, \mathbb{R}^{L+H \times K}) \to \mathbb{R}^H$$

где $K$ — количество ковариат.

Примеры: TFT, DeepAR, N-HiTS (с расширениями), Chronos-2.

**Типы ковариат:**

| Тип | Описание | Примеры |
|-----|----------|---------|
| Known future | Известны на момент прогноза | День недели, праздники, запланированные промо |
| Past-only | Известны только для прошлого | Фактическая погода, реальные продажи |
| Static | Постоянные для ряда | ID магазина, категория товара |

**Когда использовать:**
- Есть явные внешние факторы влияния
- Промо-планирование, ценообразование
- What-if анализ («что будет, если запустим акцию?»)

## Измерение 2: Архитектура

### Базовые понятия

Прежде чем разбирать архитектуры, определим ключевые компоненты.

**Encoder** — компонент, который читает входную последовательность и преобразует её в внутреннее представление (hidden states). Encoder «понимает» контекст.

$$\text{Encoder}: [x_1, x_2, ..., x_T] \to [h_1, h_2, ..., h_T]$$

**Decoder** — компонент, который генерирует выходную последовательность. Может использовать представление от encoder (в encoder-decoder архитектуре) или работать автономно (в decoder-only).

$$\text{Decoder}: h \to [y_1, y_2, ..., y_H]$$

**Linear (линейный слой)** — простейшая нейросетевая операция: $y = Wx + b$. Используется для преобразования hidden states в нужный формат выхода. Например, transformer выдаёт вектор размерности 512, а нам нужен прогноз на 24 точки — linear слой делает это преобразование (512 → 24).

```python
# Пример: hidden state → прогноз
linear = nn.Linear(in_features=512, out_features=24)
forecast = linear(hidden_state)  # shape: (batch, 24)
```

### Типы attention

Attention — механизм, позволяющий каждой позиции «смотреть» на другие позиции и взвешенно агрегировать информацию. Разные типы attention определяют, какие позиции видит каждый токен.

**Bidirectional (encoder-style)**

Каждая позиция видит ВСЕ остальные — и слева, и справа:
```
Позиция 3 видит: [1, 2, ✓3, 4, 5]
                  ↑  ↑     ↑  ↑
```
Используется в encoder-архитектурах (BERT, PatchTST). Для временных рядов: патч в середине учитывает контекст и до, и после себя.

**Causal / Unidirectional (decoder-style)**

Каждая позиция видит только ПРЕДЫДУЩИЕ (и себя):
```
Позиция 3 видит: [1, 2, ✓3, ✗, ✗]
                  ↑  ↑     
```
Используется в decoder-архитектурах (GPT, TimesFM). Главная цель — **предотвращение data leakage**: при обучении модель не может «подсмотреть» будущее, которого не будет при инференсе. Это гарантирует, что модель видит при обучении ровно то, что увидит в production.

**Cross-attention (encoder-decoder)**

Query приходит из decoder, Key и Value — из encoder. Decoder «спрашивает» у encoder, какие части контекста релевантны:

```
Encoder (контекст):     [E₁]  [E₂]  [E₃]  [E₄]  [E₅]
                          │     │     │     │     │
                          └──┬──┴──┬──┴──┬──┴──┬──┘
                             │ weights (attention)
                             ▼
Decoder (генерация):              [D₁] → [D₂] → [D₃]
```

Пример для временных рядов: decoder генерирует прогноз на день 37. Через cross-attention он «спрашивает» encoder: «какие дни истории релевантны?» День 30 (неделю назад) получает высокий вес из-за недельной сезонности, день 36 (вчера) — из-за краткосрочного тренда.

### Encoder-only

Encoder обрабатывает входную последовательность и напрямую проецирует в прогноз:

```
Input → Encoder → Linear → Forecast
```

**Примеры:** N-BEATS, N-HiTS, PatchTST, iTransformer, TSMixer, DLinear, MOMENT.

**Характеристики:**
- Bidirectional attention: каждая позиция видит все остальные
- Direct prediction: весь горизонт за один проход
- Нет накопления ошибки
- Фиксированный горизонт (обычно)

**Почему нет накопления ошибки:**

В encoder-only прогноз на каждый шаг вычисляется напрямую из истории, а не из предыдущих прогнозов:

```
[история] → Encoder → Linear → [ŷ₁, ŷ₂, ŷ₃, ŷ₄, ŷ₅] (всё сразу)
```

Прогноз ŷ₅ зависит только от истории, не от ŷ₁...ŷ₄. Если ŷ₁ ошибочен, это никак не влияет на ŷ₅ — они вычисляются независимо в одном forward pass. Математически: дисперсия ошибки не растёт с горизонтом.

**Как работает PatchTST (encoder-only):**
```
[patch₁, patch₂, ..., patchₙ] → Transformer Encoder → Flatten → Linear → [ŷ₁, ..., ŷₕ]
```

Все патчи видят друг друга через bidirectional attention. Финальный linear слой проецирует конкатенированные представления в прогноз.

### Decoder-only

Decoder генерирует прогноз авторегрессионно, используя causal attention:

```
Input → Decoder (causal) → Next token → Decoder → Next token → ...
```

**Примеры:** TimesFM, Lag-Llama, Timer, GPT4TS, Toto.

**Характеристики:**
- Causal attention: каждая позиция видит только предыдущие
- Авторегрессионная генерация (обычно)
- Гибкий горизонт без переобучения
- Накопление ошибки на длинных горизонтах

**Как decoder-only генерирует прогноз (без encoder):**

Decoder-only не использует отдельное «понимание» от encoder — он формирует понимание и генерирует прогноз в одном процессе:

```
Вход: [x₁, x₂, x₃, x₄, x₅] — история

Шаг 1: История проходит через transformer с causal attention
       [x₁, x₂, x₃, x₄, x₅] → [h₁, h₂, h₃, h₄, h₅]
       h₅ «знает» всё о предыдущих точках

Шаг 2: h₅ → Linear → ŷ₆ (первый прогноз)

Шаг 3: ŷ₆ добавляется к входу, генерируем ŷ₇
       [x₁, ..., x₅, ŷ₆] → [..., h₆] → Linear → ŷ₇

И так далее...
```

**Почему decoder-only популярен в foundation models:**

Foundation models (TimesFM, Lag-Llama, Toto) почти всегда используют decoder-only архитектуру:

- **Causal structure предотвращает leakage.** При обучении модель видит ровно то, что увидит при инференсе — будущее недоступно. Это критично для честного обучения.

- **Унифицированный подход к pre-training и inference.** И при обучении, и при инференсе модель решает одну задачу: «предскажи следующий токен». Нет разрыва между тем, чему модель учится, и тем, что она делает в production.

- **Предсказуемое масштабирование (scaling laws).** GPT показал: decoder-only трансформеры следуют scaling laws — больше параметров и данных → лучше качество, предсказуемо. Для foundation models это означает понятный путь к улучшению.

- **Гибкость горизонта без переобучения.** Модель обучена предсказывать «следующий токен». Нужен прогноз на 7 шагов? Генерируем 7 токенов. На 30 шагов? Генерируем 30. Та же модель, те же веса — переобучение не требуется.

### Encoder-Decoder

Encoder обрабатывает контекст, decoder генерирует прогноз с cross-attention к encoder:

```
Context → Encoder → [hidden states]
                         ↓ cross-attention
[start] → Decoder → ŷ₁ → Decoder → ŷ₂ → ...
```

**Примеры:** Chronos (T5), Informer, Autoformer, TimeGPT.

**Характеристики:**
- Encoder: bidirectional обработка контекста
- Decoder: авторегрессионная генерация с доступом к контексту через cross-attention
- Гибкий горизонт
- Сложнее в обучении, но мощнее для определённых задач

**Когда encoder-decoder оправдан:**

1. **Очень длинный контекст + короткий горизонт.** Encoder сжимает 10,000 точек истории в компактное представление. Decoder генерирует 24 точки прогноза, селективно обращаясь к релевантным частям через cross-attention.

2. **Разная «природа» входа и выхода.** В Chronos вход — непрерывные значения, выход — дискретные токены. Encoder работает с числами, decoder — с категориальным распределением по словарю.

3. **Задачи с «пониманием» контекста.** Encoder формирует глобальное понимание истории (тренд, сезонность, аномалии). Decoder использует это понимание для генерации. Аналогия: прочитать и понять документ (encoder), написать summary (decoder).

**Отличие от decoder-only:**

| Decoder-only | Encoder-Decoder |
|--------------|-----------------|
| Держит всю историю «перед глазами» | Сжимает историю в representation |
| Обращается к истории через self-attention | Обращается через cross-attention |
| Один компонент | Два компонента с разными ролями |

### Сравнительная таблица архитектур

| Архитектура | Attention | Генерация | Горизонт | Примеры |
|-------------|-----------|-----------|----------|---------|
| Encoder-only | Bidirectional | Direct (один проход) | Фиксированный | PatchTST, N-BEATS |
| Decoder-only | Causal | Авторегрессионный | Гибкий | TimesFM, Lag-Llama |
| Encoder-Decoder | Bi + Causal + Cross | Авторегрессионный | Гибкий | Chronos, Informer |

## Измерение 3: Тип выхода

### Point forecast (точечный прогноз)

Модель выдаёт одно значение для каждого шага горизонта:

$$\hat{y}_{t+h} = f(x_{1:t})$$

**Метрики:** MAE, MSE, MAPE, sMAPE.

**Примеры:** DLinear, N-BEATS (default), PatchTST.

**Когда достаточно:**
- Планирование с низкими рисками
- Метрика бизнеса — средняя ошибка
- Нет асимметричных costs (перепроизводство ≈ недопроизводство)

**Бизнес-примеры для point forecast:**

| Задача | Почему point достаточно |
|--------|------------------------|
| KPI dashboard | Нужна одна цифра: «ожидаем 1.2M выручки в Q3» |
| Бюджетирование | Планирование от средней величины, риски учитываются отдельно |
| Агрегированный спрос | На уровне категории ошибки усредняются, outliers сглаживаются |
| Бенчмаркинг моделей | Сравниваем по MAE/RMSE — нужна точечная оценка |

### Probabilistic forecast (вероятностный прогноз)

Модель выдаёт распределение или квантили для каждого шага:

$$p(y_{t+h} | x_{1:t}) \quad \text{или} \quad [q_{0.1}, q_{0.5}, q_{0.9}]$$

**Метрики:** CRPS, Quantile Loss, Coverage, Calibration.

**Примеры:** DeepAR, Chronos, Lag-Llama, Moirai, TFT.

**Способы получения:**

1. **Parametric distribution head** — модель предсказывает параметры распределения (μ, σ для Gaussian; α, β для Beta).
   
2. **Quantile regression** — модель обучается отдельно предсказывать каждый квантиль.

3. **Sampling** — авторегрессионная модель генерирует много траекторий, из которых строятся квантили.

4. **Conformal prediction** — поверх точечного прогноза добавляются интервалы с гарантированным покрытием.

**Когда необходим:**
- Асимметричные costs (недопоставка дороже перепроизводства)
- Планирование запасов (safety stock)
- Принятие решений под неопределённостью
- Каскадные системы (downstream models используют uncertainty)

**Бизнес-примеры для probabilistic forecast:**

| Задача | Почему нужны интервалы |
|--------|----------------------|
| **Управление запасами** | Недопоставка = потеря продаж (\$100), перезапас = списание (\$10). Оптимизируем по квантилю 90-95%, не по среднему |
| **Capacity planning** | Сервер под средний трафик перегружен 50% времени. Нужен квантиль 95-99% для SLA |
| **Финансовое планирование** | Инвесторам/CFO: «С вероятностью 90% выручка будет между X и Y» |
| **Энергетические рынки** | Покупка на day-ahead рынке: квантили нужны для оптимизации bid-стратегии |

**Ключевой триггер — асимметрия costs:**

Если cost(перепрогноз) ≈ cost(недопрогноз) → point forecast достаточен.
Если cost(перепрогноз) ≠ cost(недопрогноз) → нужен probabilistic + выбор квантиля под бизнес-логику.

### Distribution heads в разных моделях

| Модель | Тип выхода | Распределение / Метод |
|--------|------------|----------------------|
| DeepAR | Probabilistic | Gaussian, Negative Binomial, Student-t |
| Chronos | Probabilistic | Categorical (через quantization) |
| Lag-Llama | Probabilistic | Student-t |
| Moirai | Probabilistic | Mixture distribution |
| Toto | Probabilistic | Student-t mixture |
| PatchTST | Point | MSE loss |
| N-BEATS | Point / Prob | MSE или Quantile loss |

## Стратегии многошагового прогнозирования

Отдельное архитектурное решение — как именно модель генерирует прогноз на несколько шагов вперёд. Это часто упускается, но выбор стратегии может влиять на качество не меньше, чем выбор архитектуры[^taieb2012].

### Recursive (Iterated)

Обучаем модель предсказывать один шаг. Для многошагового прогноза итерируем: предсказание шага 1 становится входом для шага 2, и так далее.

```
ŷ₁ = f(x₁, ..., xₜ)
ŷ₂ = f(x₂, ..., xₜ, ŷ₁)
ŷ₃ = f(x₃, ..., xₜ, ŷ₁, ŷ₂)
...
```

**Плюсы:** Одна модель для любого горизонта. Учитывает зависимости между шагами.

**Минусы:** Накопление ошибки. Ошибка на шаге 1 влияет на шаг 2, и т.д. На длинных горизонтах прогноз «уплывает».

**Примеры:** DeepAR, классические RNN.

### Direct

Обучаем отдельную модель для каждого шага горизонта:

```
ŷ₁ = f₁(x₁, ..., xₜ)
ŷ₂ = f₂(x₁, ..., xₜ)
ŷ₃ = f₃(x₁, ..., xₜ)
...
```

**Плюсы:** Нет накопления ошибки. Каждая модель оптимизирована под свой горизонт.

**Минусы:** H моделей для горизонта H. Нет учёта зависимостей между шагами. Высокая вычислительная стоимость.

### MIMO (Multi-Input Multi-Output)

Одна модель предсказывает весь горизонт сразу:

```
[ŷ₁, ŷ₂, ..., ŷₕ] = f(x₁, ..., xₜ)
```

**Плюсы:** Одна модель. Учитывает зависимости между шагами через совместное обучение. Нет накопления ошибки.

**Минусы:** Фиксированный горизонт. Сложнее обучать при длинных горизонтах.

**Примеры:** N-BEATS, N-HiTS, PatchTST, DLinear.

**Важно: MIMO — это не бустинг.** Иногда возникает путаница из-за N-BEATS, который использует residual stacking (каждый блок работает с остатком от предыдущего). Но это разные концепции:

- **MIMO** отвечает на вопрос «как генерировать многошаговый прогноз?» — весь горизонт за один forward pass
- **Бустинг** отвечает на вопрос «как комбинировать слабые модели?» — последовательное обучение моделей на остатках
- Residual stacking в N-BEATS — это архитектурный паттерн внутри одной модели, обучаемой end-to-end

### DirRec (гибрид)

Комбинация Direct и Recursive: отдельная модель для каждого шага, но с использованием предыдущих предсказаний как входов:

```
ŷ₁ = f₁(x₁, ..., xₜ)
ŷ₂ = f₂(x₁, ..., xₜ, ŷ₁)
ŷ₃ = f₃(x₁, ..., xₜ, ŷ₁, ŷ₂)
...
```

**Плюсы:** Баланс между гибкостью и учётом зависимостей.

**Минусы:** H моделей + накопление ошибки (хотя меньше, чем в чистом Recursive).

### Сравнение стратегий

| Стратегия | Моделей | Накопление ошибки | Зависимости между шагами | Гибкость горизонта |
|-----------|---------|-------------------|-------------------------|-------------------|
| Recursive | 1 | Высокое | Да | Да |
| Direct | H | Нет | Нет | Нет |
| MIMO | 1 | Нет | Да (implicit) | Нет |
| DirRec | H | Среднее | Да | Нет |

**Эмпирические результаты:** Исследования показывают, что MIMO часто даёт лучшие результаты на практике[^comparison], особенно когда горизонт известен заранее. Recursive лучше для очень длинных или неизвестных горизонтов. Direct редко оправдан из-за высокой стоимости.

### Быстрые рекомендации

| Сценарий | Рекомендация | Почему |
|----------|--------------|--------|
| Univariate, фикс. горизонт, нужна скорость | N-BEATS, N-HiTS | Быстрые, стабильные, интерпретируемые |
| Multivariate, межканальные зависимости | iTransformer | Специально для multivariate |
| Univariate, длинный контекст | PatchTST | Патчинг решает проблему длинных рядов |
| Нужен probabilistic output | DeepAR, Lag-Llama | Нативный probabilistic forecast |
| Zero-shot, нет времени на обучение | Chronos, TimesFM | Pretrained, работают из коробки |
| Много ковариат, сложная структура | TFT | Специально для rich features |
| High-frequency, streaming | SSM-based (Mamba, S4) | Эффективный рекуррентный режим |

## Практический чек-лист

Перед выбором модели ответьте на вопросы:

**Про данные:**
- [ ] Univariate или multivariate?
- [ ] Какова длина истории? (десятки, сотни, тысячи точек)
- [ ] Есть ли ковариаты? Какого типа? (known future, past-only, static)
- [ ] Регулярные данные или с пропусками?

**Про задачу:**
- [ ] Горизонт известен заранее или варьируется?
- [ ] Нужен точечный прогноз или интервалы?
- [ ] Какова цена ошибки? Симметричная или нет?

**Про ресурсы:**
- [ ] Есть ли время на обучение или нужен zero-shot?
- [ ] GPU доступен для инференса?
- [ ] Критична ли скорость предсказания?

Ответы на эти вопросы сужают выбор до 2–3 моделей, которые стоит попробовать.
