# iTransformer: внимание наоборот

## Ключевая идея

iTransformer[^itransformer] — архитектура 2024 года, которая **инвертирует** традиционный подход к трансформерам во временных рядах. Вместо attention между точками времени — attention **между каналами** (переменными). Вместо моделирования «какие моменты прошлого важны для будущего» — моделирование «какие переменные влияют друг на друга».

Название расшифровывается как **i**nverted **Transformer**. Ключевое слово — **inverted**: инверсия измерений. Там, где PatchTST применял attention к временным патчам, iTransformer применяет attention к каналам.

**Результаты:** iTransformer превосходит PatchTST на multivariate бенчмарках и становится SOTA на момент публикации. На Weather (горизонт 720) улучшение **10% по MSE** относительно PatchTST[^itransformer].

## Проблема: почему channel-independence не всегда работает

В предыдущей главе мы обсуждали, что PatchTST использует **channel-independent** подход — каждый канал обрабатывается отдельно. Это работает как регуляризация и предотвращает переобучение.

Но что если корреляции между каналами **действительно важны**?

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    КОГДА КОРРЕЛЯЦИИ ВАЖНЫ                               │
│                                                                         │
│  Пример: прогноз потребления электроэнергии                            │
│                                                                         │
│  Канал 1: Температура       ──→ Жара → Включают кондиционеры          │
│  Канал 2: Влажность         ──→ Духота → Ещё больше кондиционеров     │
│  Канал 3: Время суток       ──→ Пик потребления в офисные часы        │
│  Канал 4: Потребление (цель) ──→ Зависит от всех выше                  │
│                                                                         │
│  Channel-Independent:                                                   │
│  [Темп.] → Transformer → Прогноз темп.    ← Не видит потребление       │
│  [Потр.] → Transformer → Прогноз потр.    ← Не видит температуру       │
│                                                                         │
│  Проблема: модель не моделирует причинно-следственные связи            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

PatchTST и DLinear обрабатывают каждый канал изолированно. Они не могут выучить, что рост температуры **предсказывает** рост потребления энергии.

## Инверсия измерений

iTransformer предлагает элегантное решение: **поменять местами роль времени и каналов**.

```

│  ──────────────────────────────────────────                             │
│  Вход: [T × C] — T точек времени, C каналов                            │
│                                                                         │

│                                                                         │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐        ┌────┐                             │
```

### Математически

**Стандартный трансформер:**
- Вход $\mathbf{X} \in \mathbb{R}^{T \times C}$ (T timesteps, C каналов)
- Токены: $T$ векторов размера $C$
- Attention: $\text{Attention}(\mathbf{X}) \in \mathbb{R}^{T \times T}$

**iTransformer:**
- Вход $\mathbf{X} \in \mathbb{R}^{T \times C}$
- **Транспонируем:** $\mathbf{X}^T \in \mathbb{R}^{C \times T}$
- Токены: $C$ векторов размера $T$
- Attention: $\text{Attention}(\mathbf{X}^T) \in \mathbb{R}^{C \times C}$

Каждый канал становится отдельным токеном, содержащим **полную историю** этой переменной.

### Ключевые компоненты

**1. Variate Embedding**

Каждый канал (variate) преобразуется из временного ряда длины $L$ в эмбеддинг размера $D$:

$$\mathbf{z}_c = \text{MLP}(\mathbf{x}_c), \quad \mathbf{x}_c \in \mathbb{R}^L, \; \mathbf{z}_c \in \mathbb{R}^D$$

MLP здесь — простой линейный слой или двухслойная сеть. Эмбеддинг содержит **сжатую информацию** о всей истории канала.

**2. Attention между каналами**

Self-attention работает на матрице $\mathbf{Z} \in \mathbb{R}^{C \times D}$:

$$\text{Attention}(\mathbf{Z}) = \text{softmax}\left(\frac{\mathbf{Z}\mathbf{W}_Q (\mathbf{Z}\mathbf{W}_K)^T}{\sqrt{d_k}}\right) \mathbf{Z}\mathbf{W}_V$$

Attention-матрица имеет размер $C \times C$ — каждый канал «смотрит» на все остальные каналы.

**3. FFN для временных паттернов**

Feed-forward network работает с каждым каналом независимо:

$$\text{FFN}(\mathbf{z}) = \mathbf{W}_2 \cdot \text{GELU}(\mathbf{W}_1 \mathbf{z} + \mathbf{b}_1) + \mathbf{b}_2$$

FFN отвечает за моделирование **временных зависимостей** внутри каждого канала. Это похоже на то, как в стандартном трансформере attention моделирует связи между токенами, а FFN — обработку каждого токена.

### Почему это работает

**Разделение ответственности:**
- **Attention:** межканальные зависимости (температура → потребление)
- **FFN:** временные паттерны (сезонность, тренды)

**Эффективность attention:**
- Attention-матрица $C \times C$ вместо $T \times T$
- При $C=7$ и $T=512$: $49$ vs $262,144$ элементов

**Богатые токены:**
- Каждый токен содержит полную историю канала
- В отличие от point-wise, где токен — одно число

## Сравнение: PatchTST vs iTransformer

| Аспект | PatchTST | iTransformer |
|--------|----------|--------------|
| **Токены** | Патчи времени | Каналы |
| **Attention** | Между патчами (время) | Между каналами |
| **Временные паттерны** | Через attention | Через FFN |
| **Межканальные связи** | Не моделирует (CI) | Моделирует (CD) |
| **Сложность attention** | $O(N^2)$ где $N = L/P$ | $O(C^2)$ |
| **Лучше для** | Независимые каналы | Связанные каналы |

```
│  ┌──────────────────────────────────────────────────────────────┐      │
│  │                       Ось времени →                          │      │
│  │  Ch1: [patch₁][patch₂][patch₃][patch₄] ─→ Attention ─→ pred  │      │
```

## Результаты

iTransformer показывает сильные результаты, особенно на multivariate бенчмарках:

| Датасет | Горизонт | PatchTST | iTransformer | Улучшение |
|---------|----------|----------|--------------|-----------|
| Weather | 96 | 0.177 | **0.174** | 1.7% |
| Weather | 720 | 0.323 | **0.291** | **9.9%** |
| Traffic | 96 | 0.421 | **0.395** | 6.2% |
| ECL | 96 | 0.197 | **0.178** | 9.6% |

**Ключевое наблюдение:** Преимущество iTransformer **растёт с горизонтом**. На длинных горизонтах межканальные зависимости становятся важнее.

### Почему улучшение сильнее на длинных горизонтах

На коротких горизонтах (96 точек) «инерция» данных позволяет предсказывать по истории одного канала. На длинных горизонтах (720+ точек):

1. **Uncertainty накапливается** — нужна информация из других каналов для корректировки
2. **Сезонные паттерны** проявляются через корреляции между переменными
3. **Причинно-следственные связи** становятся критичными

## Код: iTransformer

### NeuralForecast

```python
from neuralforecast import NeuralForecast
from neuralforecast.models import iTransformer
from neuralforecast.losses.pytorch import MAE

HORIZON = 96

model = iTransformer(
    h=HORIZON,
    input_size=512,           # длина lookback

    # Transformer параметры
    n_series=None,            # автоматически из данных
    hidden_size=512,          # размерность эмбеддингов
    n_heads=8,                # число attention heads
    e_layers=3,               # число encoder layers
    d_ff=512,                 # размерность FFN

    # Обучение
    loss=MAE(),
    max_steps=1000,
    learning_rate=1e-4,
    batch_size=32,

    scaler_type='standard',
    random_seed=42
)

nf = NeuralForecast(models=[model], freq='H')
nf.fit(df=train_df)
forecasts = nf.predict()
```

### Важно: multivariate формат данных

iTransformer требует **multivariate** формат — все каналы должны быть в одном DataFrame:

```python
# Формат для NeuralForecast с multivariate
# unique_id | ds | y | exog_1 | exog_2 | ...

import pandas as pd

df = pd.DataFrame({
    'unique_id': ['series_1'] * 100,
    'ds': pd.date_range('2020-01-01', periods=100, freq='H'),
    'y': target_values,           # целевой канал
    'temperature': temp_values,   # дополнительный канал
    'humidity': humidity_values,  # дополнительный канал
})
```

## Гиперпараметры

| Параметр | Типичные значения | Комментарий |
|----------|-------------------|-------------|
| `input_size` | 336, 512, 720 | Длина lookback |
| `hidden_size` | 256, 512 | Размерность эмбеддингов |
| `n_heads` | 4, 8 | Число attention heads |
| `e_layers` | 2, 3, 4 | Число encoder layers |
| `d_ff` | = hidden_size | Размерность FFN |

**Рекомендации:**

1. **hidden_size** должен быть достаточно большим, чтобы вместить информацию о $L$ точках истории
2. **n_heads** — меньше, чем число каналов $C$
3. **e_layers** — 2-4 обычно достаточно

## Сильные стороны

**Моделирование межканальных зависимостей.** Главное преимущество — attention между каналами позволяет выучить корреляции.

**Эффективность при большом числе timesteps.** Attention $C \times C$ вместо $T \times T$. При $T >> C$ — значительная экономия.

**Длинные горизонты.** Преимущество растёт с горизонтом, где межканальные связи критичны.

**Простая архитектура.** Стандартный трансформер, только с инверсией измерений.

## Ограничения

**Требует multivariate данные.** Для univariate задач iTransformer избыточен — нет каналов для attention.

**Масштабируемость по каналам.** При $C > 100$ каналов attention-матрица становится большой. PatchTST лучше масштабируется.

**Не все корреляции полезны.** Если каналы действительно независимы, attention между ними — шум.

**Фиксированный горизонт.** Как и другие encoder-only модели.

## Когда выбирать iTransformer

✅ **Используйте iTransformer, если:**
- Multivariate задача с важными межканальными зависимостями
- Умеренное число каналов (< 50)
- Длинные горизонты прогнозирования
- Данные из одного домена с явными корреляциями (метео, энергетика, финансы)

❌ **Рассмотрите альтернативы, если:**
- Univariate задача → N-HiTS, DLinear
- Каналы независимы → PatchTST (channel-independent)
- Очень много каналов (> 100) → TSMixer, PatchTST
- Zero-shot требуется → Chronos, TimesFM

## Выводы

1. **Инверсия измерений** — элегантная идея: attention между каналами вместо timesteps.

2. **Разделение ответственности:** attention моделирует межканальные связи, FFN — временные паттерны.

3. **Преимущество на длинных горизонтах:** чем дальше прогноз, тем важнее корреляции между переменными.

4. **Выбор между PatchTST и iTransformer:**
   - Каналы независимы → PatchTST
   - Каналы связаны → iTransformer

5. **Практически:** iTransformer — первый выбор для multivariate задач с явными межканальными зависимостями.
