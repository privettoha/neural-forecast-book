# Трансформеры для временных рядов: проблемы

## Ключевая идея

Трансформеры[^attention] произвели революцию в NLP и компьютерном зрении. Логично было ожидать такого же успеха во временных рядах. Однако **прямой перенос не работает**: механизм self-attention, созданный для текста, плохо подходит для непрерывных последовательностей с временной структурой. Эта глава объясняет, почему vanilla-трансформеры неэффективны для прогнозирования и какие архитектурные решения пытались это исправить.

## Краткая история: от NLP к временным рядам

```

│                    ХРОНОЛОГИЯ ТРАНСФОРМЕРОВ В TIME SERIES              │
│                                                                         │

│    │                                                                    │
│  2018  BERT, GPT — NLP-революция                                       │

│  2019  Первые попытки: LogTrans, Temporal Fusion Transformer           │
│    │                                                                    │
│  2021  Informer (AAAI Best Paper) — sparse attention для длинных рядов │
│    │   Autoformer — auto-correlation вместо attention                  │
│    │                                                                    │

```

После успеха BERT[^bert] и GPT[^gpt] исследователи начали применять трансформеры к временным рядам. Первые результаты выглядели многообещающе — Informer[^informer] получил Best Paper Award на AAAI 2021. Но в 2022 году статья «Are Transformers Effective for Time Series Forecasting?»[^dlinear] показала: **простейшая линейная модель с одним слоем превосходит все трансформерные архитектуры**.

Что пошло не так?

## Проблема 1: Permutation Invariance

Механизм self-attention **по своей природе не различает порядок элементов**. Для последовательности токенов $\{x_1, x_2, \ldots, x_n\}$ вычисляется:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

где $Q = XW_Q$, $K = XW_K$, $V = XW_V$.

**Критическое наблюдение:** Если переставить строки в $X$, attention-веса изменятся только пропорционально — без positional encoding модель не знает, что $x_1$ идёт перед $x_2$.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    PERMUTATION INVARIANCE                               │
│                                                                         │
│  Self-attention вычисляет сходство между ВСЕМИ парами:                 │
│                                                                         │
│      x₁ ←──────→ x₂                                                    │
│       ↖         ↗                                                      │
│        ↘       ↙                                                       │
│          x₃                                                            │
│                                                                         │
│  Без positional encoding: Attention(x₁,x₂,x₃) = Attention(x₃,x₁,x₂)   │
│                                                                         │
│  ─────────────────────────────────────────────────────────────────      │
│                                                                         │
│  Для текста:   "Кошка сидит на коврике"                                │
│                 ≈ "На коврике сидит кошка"                             │
│                 (смысл примерно сохраняется)                           │
│                                                                         │
│  Для рядов:    [100, 105, 110] — растущий тренд                        │
│                [110, 100, 105] — хаотичные колебания                   │
│                 (порядок — это ВСЁ!)                                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Positional Encoding — частичное решение

Трансформеры добавляют positional encoding (PE) к эмбеддингам:

$$\text{PE}(pos, 2i) = \sin\left(\frac{pos}{10000^{2i/d}}\right), \quad \text{PE}(pos, 2i+1) = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$

Но PE — это **фиксированный сигнал**, добавляемый к входу. Модель должна **научиться** использовать его для понимания порядка. Эксперименты показывают[^dlinear]: на практике attention-веса слабо коррелируют с временной близостью — модель часто «смотрит» на далёкие точки вместо соседних.

**Для текста** это нормально: слово в начале предложения может быть связано со словом в конце. **Для временных рядов** это проблема: значение в момент $t$ почти всегда сильнее связано с $t-1$, чем с $t-100$.

## Проблема 2: Квадратичная сложность

Self-attention имеет сложность $O(n^2)$ по памяти и вычислениям, где $n$ — длина последовательности.

| Длина входа | Attention-матрица | Память (float32) |
|-------------|-------------------|------------------|
| 96 | 9,216 элементов | 36 KB |
| 512 | 262,144 элементов | 1 MB |
| 2,048 | 4,194,304 элементов | 16 MB |
| 8,192 | 67,108,864 элементов | 256 MB |

Для NLP последовательности 512-2048 токенов — норма. Но временной ряд с часовой гранулярностью за месяц — это 720 точек, за год — 8,760 точек. **Квадратичная сложность делает длинные ряды непрактичными**.

### Попытки решения: sparse attention

Исследователи предложили несколько подходов для снижения сложности:

**Informer (2021)**[^informer] — ProbSparse attention. Вместо вычисления всех пар, выбираем «важные» queries на основе KL-дивергенции:

$$\bar{Q} = \text{argmax}_Q \left( \text{KL}(q_i || \text{Uniform}) \right)$$

Только queries с «неравномерным» распределением attention используются полностью. Сложность снижается до $O(n \log n)$.

**Autoformer (2021)**[^autoformer] — Auto-Correlation вместо attention. Заменяет dot-product внимание на корреляцию во временной области:

$$\text{AutoCorrelation}(Q, K, V) = \text{softmax}\left(\mathcal{R}_{Q,K}\right) \cdot \text{Roll}(V)$$

где $\mathcal{R}_{Q,K}$ — автокорреляция между Q и K, а $\text{Roll}$ — циклический сдвиг. Интуиция: вместо поиска похожих токенов — поиск похожих паттернов с учётом временного сдвига.

**FEDformer (2022)**[^fedformer] — Frequency Enhanced Decomposition. Attention в частотной области через FFT:

$$\text{FEB}(Q, K, V) = \mathcal{F}^{-1}\left(\mathcal{F}(Q) \odot \mathcal{F}(K)^* \odot \mathcal{F}(V)\right)$$

Сложность $O(n \log n)$ благодаря FFT.

```
┌─────────────────────────────────────────────────────────────────────────┐
│              СРАВНЕНИЕ ATTENTION-МЕХАНИЗМОВ                            │
│                                                                         │
│  Модель          Сложность    Основная идея                            │
│  ─────────────────────────────────────────────────────────────────      │
│  Vanilla         O(n²)        Полный attention                         │
│  Informer        O(n log n)   Sparse selection of queries              │
│  Autoformer      O(n log n)   Auto-correlation в time domain           │
│  FEDformer       O(n log n)   Attention в frequency domain             │
│                                                                         │
│  Все эти модели проиграли DLinear O(n) с одним слоем.                  │
└─────────────────────────────────────────────────────────────────────────┘
```

## Проблема 3: Токенизация

В NLP один токен = одно слово (или часть слова). Токен несёт **семантическую нагрузку**: «кошка» означает конкретное понятие.

Во временных рядах один timestep — это **одно число**. Какую «семантику» несёт значение 105.3? Без контекста — никакую.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ТОКЕНЫ: NLP vs TIME SERIES                          │
│                                                                         │
│  NLP:                                                                   │
│  "The cat sat on the mat"                                              │
│   ↓   ↓   ↓   ↓  ↓   ↓                                                 │
│  [The][cat][sat][on][the][mat]  ← 6 семантически значимых токенов      │
│                                                                         │
│  Time Series:                                                           │
│  [100, 102, 105, 103, 108, 110]                                        │
│    ↓    ↓    ↓    ↓    ↓    ↓                                          │
│  [100][102][105][103][108][110] ← 6 чисел без контекста                │
│                                                                         │
│  Проблема: attention между числами 100 и 108 не имеет смысла           │
│  без понимания, что это соседние точки тренда.                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**Следствие:** Attention-веса во временных рядах часто **шумные и неинтерпретируемые**. Модель не «понимает», что точки 100→102→105 — это растущий тренд.

### Point-wise vs Patch-wise токенизация

Решение проблемы токенизации — **патчинг**: группировка соседних точек в один токен.

Вместо:
```
[x₁, x₂, x₃, x₄, x₅, x₆, x₇, x₈] → 8 токенов
```

Делаем:
```
[[x₁, x₂], [x₃, x₄], [x₅, x₆], [x₇, x₈]] → 4 токена (patches)
```

Каждый патч содержит локальный контекст — информацию о направлении, скорости изменения. Это основа **PatchTST** (глава 21).

## Проблема 4: Channel Mixing vs Channel Independence

Многомерные временные ряды содержат несколько переменных (channels). Например: температура, давление, влажность.

**Вопрос:** Должна ли модель моделировать зависимости между каналами?

Интуитивный ответ — да. Но эксперименты показывают[^patchtst]: **channel-independent** модели часто работают лучше.

```
┌─────────────────────────────────────────────────────────────────────────┐
│              CHANNEL MIXING vs CHANNEL INDEPENDENCE                     │
│                                                                         │
│  Channel-Dependent (CD):                                                │
│  ┌─────────────────────────────────────────────┐                       │
│  │  Все каналы → Общий Transformer → Прогнозы  │                       │
│  └─────────────────────────────────────────────┘                       │
│  • Моделирует корреляции между переменными                             │
│  • Больше параметров, риск переобучения                                │
│  • Работает при сильных межканальных зависимостях                      │
│                                                                         │
│  Channel-Independent (CI):                                              │
│  ┌───────────────────┐  ┌───────────────────┐                          │
│  │ Канал 1 → Transf. │  │ Канал 2 → Transf. │  ... (shared weights)   │
│  └───────────────────┘  └───────────────────┘                          │
│  • Каждый канал обрабатывается отдельно                                │
│  • Меньше параметров, лучше обобщение                                  │
│  • Работает на большинстве бенчмарков                                  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**Парадокс:** Трансформеры, созданные для моделирования зависимостей между токенами, работают лучше, когда каналы обрабатываются **независимо**. Причина — переобучение на шумные корреляции в обучающих данных.

iTransformer (глава 22) предлагает альтернативный подход: attention **между каналами**, а не между timesteps.

## Урок DLinear: сложность ≠ качество

В 2022 году статья «Are Transformers Effective for Time Series Forecasting?»[^dlinear] показала результаты, которые шокировали сообщество:

| Модель | MACs (×10⁶) | MSE на ETTh1 |
|--------|-------------|--------------|
| Informer | 1,720 | 0.304 |
| Autoformer | 1,630 | 0.227 |
| FEDformer | 4,130 | 0.214 |
| **DLinear** | **0.51** | **0.212** |

**DLinear — один линейный слой** — превзошёл все трансформеры, используя в 3000+ раз меньше вычислений.

Выводы авторов:
1. **Positional encoding недостаточен** для передачи временной структуры
2. **Sparse attention не решает** фундаментальную проблему permutation invariance
3. **Трансформеры переобучаются** на шуме, воспринимая резкие изменения как паттерны

## Что работает: ключевые инсайты

После DLinear сообщество переосмыслило подход к трансформерам во временных рядах:

### 1. Патчинг вместо point-wise токенизации

**PatchTST**[^patchtst]: группировка соседних точек создаёт семантически значимые токены. Attention между патчами имеет смысл — это сравнение локальных паттернов.

### 2. Инверсия измерений

**iTransformer**[^itransformer]: вместо attention между timesteps — attention между каналами. Временные зависимости моделируются через MLP.

### 3. Decomposition + Attention

**Autoformer**, **FEDformer**: сначала декомпозиция на тренд/сезонность, потом attention. Но даже это не спасло от DLinear.

### 4. Hybrid архитектуры

Современные модели комбинируют трансформеры с MLP, convolutions, или используют трансформеры только для части задачи.

## Когда трансформеры всё-таки работают

Несмотря на критику, трансформеры имеют свою нишу:

✅ **Foundation models** (Chronos, TimesFM, Moirai) — pretrained трансформеры, которые выучили паттерны из миллионов рядов. Zero-shot возможности.

✅ **Probabilistic forecasting** — механизм attention полезен для моделирования uncertainty.

✅ **Cross-variate reasoning** — когда корреляции между переменными критичны (iTransformer).

✅ **Длинные зависимости** — если паттерн действительно зависит от далёких точек (редко).

❌ **Стандартные бенчмарки** — PatchTST и iTransformer улучшили ситуацию, но MLP-модели (N-HiTS, TSMixer) остаются конкурентоспособными.

## Выводы

1. **Vanilla-трансформеры плохо работают** на временных рядах из-за permutation invariance, квадратичной сложности и неинформативной токенизации.

2. **Sparse attention** (Informer, Autoformer, FEDformer) снижает сложность, но не решает фундаментальные проблемы.

3. **DLinear показал:** сложность ≠ качество. Простая линейная модель может быть лучше.

4. **Современные решения:** патчинг (PatchTST), инверсия измерений (iTransformer), foundation models (Chronos, TimesFM).

5. **Практический вывод:** Не используйте vanilla-трансформеры для временных рядов. Если нужен трансформер — выбирайте PatchTST или iTransformer.

В следующей главе рассмотрим **PatchTST** — первую трансформерную архитектуру, которая убедительно ответила на критику DLinear.
