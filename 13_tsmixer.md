# TSMixer: перемешивание вместо внимания

## Ключевая идея

TSMixer[^tsmixer] — это ответ Google на вопрос, который мучил исследователей несколько лет: почему трансформеры, доминирующие в NLP и computer vision, показывают неоднозначные результаты на временных рядах?

Вместо того чтобы усложнять механизм внимания, авторы пошли в противоположном направлении — взяли максимально простую архитектуру из компьютерного зрения (MLP-Mixer[^mlpmixer]) и адаптировали её для временных рядов.

Результат удивил многих: модель из обычных полносвязных слоёв, которая просто «перемешивает» информацию по двум осям — **времени** и **признакам** — оказалась конкурентоспособна с трансформерами и при этом значительно проще.

**Результаты:** TSMixer — первая мультивариативная модель, достигшая уровня SOTA univariate моделей. Превосходные результаты на M5 retail benchmark[^tsmixer].

## Контекст: почему трансформеры буксуют

В 2020–2022 годах вышла серия работ, адаптирующих трансформеры для временных рядов: Informer[^informer], Autoformer[^autoformer], FEDformer[^fedformer]. Каждая предлагала свой способ — sparse attention, auto-correlation, frequency-domain attention.

А затем в 2022 году вышла статья «Are Transformers Effective for Time Series Forecasting?»[^dlinear], которая показала неудобную правду: **простая линейная модель (DLinear) обходит большинство сложных архитектур** на стандартных бенчмарках.

Почему так происходит?

**Permutation invariance.** Self-attention инвариантен к перестановкам — порядок токенов не влияет на веса внимания без позиционного кодирования. Для временных рядов порядок — это всё, и positional embeddings могут быть недостаточны.

**Point-wise attention.** Трансформер применяет внимание к отдельным точкам ряда. Но точка ряда — просто число, не токен с семантикой. Паттерны проявляются в последовательностях точек, не в отдельных значениях.

**Квадратичная сложность.** $O(L^2)$ по длине последовательности. Для длинных рядов приходится идти на компромиссы (sparse attention), которые теряют информацию.

TSMixer предлагает радикальное решение: **отказаться от attention** в пользу более простых операций.

## От MLP-Mixer к TSMixer

MLP-Mixer[^mlpmixer] был предложен Google в 2021 году для компьютерного зрения. Идея: изображение разбивается на патчи, но вместо self-attention используются два типа MLP:

- **Token-mixing MLP** — перемешивает информацию между патчами (пространственными позициями)
- **Channel-mixing MLP** — перемешивает информацию между признаками

TSMixer переносит эту идею на временные ряды. Многомерный ряд — матрица $\mathbf{X} \in \mathbb{R}^{T \times C}$, где $T$ — временные шаги, $C$ — каналы (переменные).

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Многомерный временной ряд                        │
│                                                                     │
│              t₁    t₂    t₃    t₄   ...   tₜ                       │
│            ┌─────┬─────┬─────┬─────┬─────┬─────┐                    │
│  Channel 1 │  x  │  x  │  x  │  x  │ ... │  x  │  ← Time-mixing    │
│            ├─────┼─────┼─────┼─────┼─────┼─────┤    (по строке)    │
│  Channel 2 │  x  │  x  │  x  │  x  │ ... │  x  │                    │
│            ├─────┼─────┼─────┼─────┼─────┼─────┤                    │
│  Channel 3 │  x  │  x  │  x  │  x  │ ... │  x  │                    │
│            └─────┴─────┴─────┴─────┴─────┴─────┘                    │
│               ↑                                                     │
│         Feature-mixing (по столбцу)                                │
└─────────────────────────────────────────────────────────────────────┘
```

![tsmixer](/Users/antonkiriltsev/Desktop/neural-forecast-book/images/TSMixer.png)

**Time-mixing** — перемешивание вдоль оси времени. Применяется к каждому каналу независимо. Учит временные паттерны: как сегодня связано со вчера.

**Feature-mixing** — перемешивание вдоль оси признаков. Применяется к каждому моменту независимо. Учит зависимости между переменными: как продажи категории A связаны с категорией B.

**⚠️ Предостережение:** Feature-mixing — палка о двух концах. Если в данных есть «мусорные» каналы (шумные сенсоры, переменные с пропусками) или переменные с очень разным масштабом, feature-mixing может «загрязнить» прогноз хороших каналов шумом из плохих. Это одна из причин, почему Channel Independence (CI) иногда выигрывает даже на многомерных данных.

## Структура блока TSMixer

Базовый блок состоит из двух последовательных подблоков с residual connections.

### Time-mixing подблок

```
Input: X ∈ ℝ^(T×C)
    ↓
Transpose → X^T ∈ ℝ^(C×T)
    ↓
LayerNorm
    ↓
MLP (применяется к каждой строке = истории канала)
    ↓
Transpose → ℝ^(T×C)
    ↓
+ Residual
    ↓
Output: ℝ^(T×C)
```

Транспонирование нужно, чтобы MLP работал вдоль временной оси. После транспонирования каждая строка — история одного канала.

### Feature-mixing подблок

```
Input: X ∈ ℝ^(T×C)
    ↓
LayerNorm
    ↓
MLP (применяется к каждой строке = срезу всех каналов)
    ↓
+ Residual
    ↓
Output: ℝ^(T×C)
```

Транспонирование не нужно — MLP сразу работает вдоль оси признаков. Каждая строка — срез всех каналов в один момент времени.

### Полный блок

$$\mathbf{X}' = \mathbf{X} + \text{MLP}_{\text{time}}(\text{LayerNorm}(\mathbf{X})^T)^T, \quad \mathbf{X} \in \mathbb{R}^{T \times C}$$

$$\mathbf{X}'' = \mathbf{X}' + \text{MLP}_{\text{feature}}(\text{LayerNorm}(\mathbf{X}')), \quad \mathbf{X}'' \in \mathbb{R}^{T \times C}$$

Модель состоит из нескольких таких блоков, уложенных последовательно.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    TSMixer Block (детально)                         │
│                                                                     │
│  Input X ∈ ℝ^(T×C)                                                 │
│       │                                                             │
│       ▼                                                             │
│  ╔═══════════════════════════════════════════════════════════════╗ │
│  ║                   TIME-MIXING SUBLAYER                        ║ │
│  ║                                                               ║ │
│  ║   X ──► Transpose ──► X^T ∈ ℝ^(C×T)                          ║ │
│  ║              │                                                ║ │
│  ║              ▼                                                ║ │
│  ║         LayerNorm                                             ║ │
│  ║              │                                                ║ │
│  ║              ▼                                                ║ │
│  ║   ┌──────────────────────────────────┐                       ║ │
│  ║   │  MLP applied to each row (C×T)   │  ← Каждая строка =    ║ │
│  ║   │  Row 1: [t₁,t₂,...,tₜ] → MLP    │    история канала     ║ │

│  ║   │  ...                             │                       ║ │

│  ║              │                                                ║ │

│  ║              │                                                ║ │
│  ║              ▼                                                ║ │
│  ║         + Residual (X)                                        ║ │
│  ╚═══════════════════════════════════════════════════════════════╝ │
│       │                                                             │
│       ▼  X' ∈ ℝ^(T×C)                                              │
│       │                                                             │
│  ╔═══════════════════════════════════════════════════════════════╗ │
│  ║                  FEATURE-MIXING SUBLAYER                      ║ │
│  ║                                                               ║ │
│  ║   X' ──► LayerNorm                                            ║ │
│  ║              │                                                ║ │
│  ║              ▼                                                ║ │
│  ║   ┌──────────────────────────────────┐                       ║ │
│  ║   │  MLP applied to each row (T×C)   │  ← Каждая строка =    ║ │
│  ║   │  Row 1: [c₁,c₂,...,cₖ] → MLP    │    срез всех каналов  ║ │
│  ║   │  Row 2: [c₁,c₂,...,cₖ] → MLP    │    в момент t         ║ │
│  ║   │  ...                             │                       ║ │
│  ║   └──────────────────────────────────┘                       ║ │
│  ║              │                                                ║ │
│  ║              ▼                                                ║ │
│  ║         + Residual (X')                                       ║ │
│  ╚═══════════════════════════════════════════════════════════════╝ │
│       │                                                             │
│       ▼                                                             │
│  Output X'' ∈ ℝ^(T×C)                                              │
└─────────────────────────────────────────────────────────────────────┘
```

**Ключевое отличие:** В time-mixing нужно транспонирование, чтобы MLP работал вдоль оси времени. В feature-mixing транспонирование не нужно — данные уже в нужной ориентации.

## Temporal Projection

После стека mixer-блоков нужно превратить представление $T \times C$ в прогноз $H \times C$. TSMixer делает это через проекцию:

$$\hat{\mathbf{Y}} = \mathbf{W} \cdot \mathbf{X}_{\text{final}} + \mathbf{b}$$

где $\mathbf{W} \in \mathbb{R}^{H \times T}$ проецирует $T$ исторических значений в $H$ будущих для каждого канала независимо.

**Важное отличие от DLinear:** В оригинальном DLinear проекция — это один линейный слой. В TSMixer проекция часто **многослойная** (MLP), что позволяет модели выучивать более сложные нелинейные зависимости на финальном этапе. Авторы TSMixer говорят: сила модели не только в проекции, но и в качественном представлении, которое строят mixer-блоки.

## Почему mixing работает

На первый взгляд, TSMixer делает меньше, чем трансформер: нет глобального внимания. Но именно это ограничение — преимущество.

**Индуктивное смещение.** Time-mixing применяется к каждому каналу независимо — неявное предположение, что временные паттерны похожи для разных переменных. Feature-mixing применяется к каждому моменту независимо — предположение, что зависимости между переменными стабильны во времени. Для большинства рядов эти предположения разумны.

**Меньше параметров.** MLP для time-mixing: $O(T \times d)$ параметров. Для feature-mixing: $O(C \times d)$. Линейно по длине и количеству каналов, в отличие от квадратичной сложности attention.

**Устойчивость к шуму.** Self-attention вычисляет веса на основе сходства между точками. На зашумлённых данных модель «обращает внимание» на случайные совпадения. MLP учится фиксированному преобразованию, менее чувствительному к флуктуациям.

## Channel Independence vs Channel Mixing

TSMixer вводит важную дискуссию: **нужно ли моделировать зависимости между каналами?**

| Подход | Модели | Идея |
|--------|--------|------|
| **Channel Independence (CI)** | N-BEATS, N-HiTS, PatchTST | Каждый канал обрабатывается отдельно |
| **Channel Dependent (CD)** | TSMixer, iTransformer | Каналы взаимодействуют через feature-mixing |

**Аргументы за CI:**
- Меньше параметров, меньше переобучения
- Robustness к spurious correlations между каналами
- Работает даже когда каналы семантически разные

**Аргументы за CD (TSMixer):**
- Если каналы реально связаны (продажи разных категорий в одном магазине), feature-mixing улавливает это
- Может давать лучшие результаты на данных с сильными межканальными зависимостями

**Эмпирика:** На разных датасетах побеждают разные подходы. TSMixer показывает преимущество на M5 (ритейл), где категории товаров действительно связаны. На ETT (электричество) преимущество меньше[^tsmixer].

## TSMixer-Ext: работа с ковариатами

Базовый TSMixer работает только с историей целевых переменных. TSMixer-Ext расширяет архитектуру для ковариат:

- **Статические признаки:** категория товара, регион
- **Известные будущие:** день недели, праздники
- **Временные признаки:** hour-of-day, month-of-year

Архитектура TSMixer-Ext:
1. **Align stage:** приводит разные типы признаков к общему формату
2. **Mixing stage:** расширенные mixer-блоки
3. **Projection stage:** финальная проекция

Мы не будем детально разбирать TSMixer-Ext — важно знать, что расширение существует.

## Сильные стороны

**Работа с многомерными рядами.** В отличие от N-BEATS/N-HiTS, TSMixer нативно работает с группами связанных переменных. Если продажи категории A влияют на B, feature-mixing может это уловить.

**Простота.** Линейные слои, LayerNorm, GELU-активации. Нет сложных механизмов, требующих специальной инициализации.

**Масштабируемость.** Линейная сложность по длине ряда — можно работать с длинными историями без sparse attention.

**Наследие.** TSMixer стал backbone для TTMs[^ttms] — foundation model от IBM для временных рядов.

## Ограничения

**Необходимость многомерных данных.** Feature-mixing имеет смысл только при нескольких связанных переменных. Для одномерного ряда TSMixer сводится к time-mixing, преимущества теряются.

**Фиксированная структура зависимостей.** Mixing применяется одинаково ко всем позициям и каналам. Модель не может адаптивно «решать», на что обратить внимание.

**Чувствительность к порядку каналов.** Feature-mixing MLP принимает каналы в определённом порядке. Если порядок изменится — нужно переобучать.

**Относительная новизна.** TSMixer появился в 2023 году, практического опыта меньше, чем для N-BEATS.

## Код: TSMixer на Store Sales

```python
from neuralforecast import NeuralForecast
from neuralforecast.models import TSMixer
from neuralforecast.losses.pytorch import MAE

HORIZON = 16
INPUT_SIZE = 64

model = TSMixer(
    h=HORIZON,
    input_size=INPUT_SIZE,
    n_series=None,              # определится из данных
    loss=MAE(),
    max_steps=1000,
    
    # Архитектура mixer
    n_block=4,                  # количество mixer-блоков
    ff_dim=64,                  # размерность feed-forward
    dropout=0.1,
    
    scaler_type='standard',
    random_seed=42
)

# ⚠️ ВАЖНО: TSMixer требует, чтобы количество каналов C
# в fit() и predict() совпадало. Если при инференсе
# появятся новые каналы или исчезнут старые — модель упадёт.

nf = NeuralForecast(models=[model], freq='D')

forecasts = nf.predict()
```

### Подготовка многомерных данных

TSMixer ожидает данные в long format с несколькими unique_id:

```python
def prepare_multivariate_data(df, group_col, time_col, value_col, channel_col):
    """
    Преобразует данные для TSMixer.
    Каждый канал — отдельный unique_id.
    """
    df = df.copy()
    df['unique_id'] = df[group_col].astype(str) + '_' + df[channel_col].astype(str)
    df = df.rename(columns={time_col: 'ds', value_col: 'y'})
    return df[['unique_id', 'ds', 'y']]

# Продажи по магазинам и категориям
train_prepared = prepare_multivariate_data(
    raw_data,
    group_col='store_id',
    time_col='date',
    value_col='sales',
    channel_col='category'
)
```

## Гиперпараметры

| Параметр | Типичные значения | Комментарий |
|----------|-------------------|-------------|
| `n_block` | 2-8 | Больше блоков → выше ёмкость |
| `ff_dim` | 32-128 | Размерность скрытого слоя в MLP |
| `dropout` | 0.0-0.3 | Регуляризация |
| `input_size` | 2H-8H | Длина входного окна |

## Когда выбирать TSMixer

✅ **Используйте TSMixer, если:**
- Несколько связанных временных рядов (продажи категорий, метрики сервисов)
- Есть основания полагать, что каналы влияют друг на друга
- Нужна простая и быстрая модель для multivariate forecasting

❌ **Рассмотрите альтернативы, если:**
- Одномерный ряд → N-BEATS, N-HiTS
- Каналы семантически независимы → PatchTST (channel-independent)
- Нужна явная интерпретируемость межканальных связей → iTransformer (глава 16)

## Выводы

1. **TSMixer = MLP-Mixer для временных рядов.** Time-mixing учит временные паттерны, feature-mixing — зависимости между каналами.

2. **Простота побеждает.** Никакого attention — только MLP, LayerNorm, residual connections.

3. **Channel mixing vs independence** — открытый вопрос. TSMixer выигрывает на данных с реальными межканальными зависимостями.

4. **Наследие:** TSMixer стал основой для TTMs и других foundation models.

В следующей главе рассмотрим DLinear — ещё более радикальную критику сложности, где один линейный слой конкурирует с трансформерами.
