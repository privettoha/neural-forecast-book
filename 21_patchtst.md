# PatchTST: патчинг решает проблему трансформеров

## Ключевая идея

PatchTST[^patchtst] — это архитектура 2023 года, которая показала: **трансформеры могут работать для временных рядов**, если правильно токенизировать входные данные. Вместо того чтобы подавать каждую точку как отдельный токен (point-wise), PatchTST группирует соседние точки в **патчи** (patch-wise). Это решает сразу несколько проблем: токены становятся семантически значимыми, attention-матрица уменьшается, модель может использовать более длинный контекст.

Название расшифровывается как **Patch** **T**ime **S**eries **T**ransformer. Ключевое слово — **patch**: как в Vision Transformer (ViT)[^vit] изображение разбивается на патчи пикселей, так и временной ряд разбивается на патчи последовательных точек.

**Результаты:** PatchTST превзошёл DLinear на большинстве бенчмарков, вернув трансформерам конкурентоспособность. На ETTh1 (горизонт 336) улучшение **21% по MSE** относительно DLinear[^patchtst].

## Две ключевые идеи

PatchTST строится на двух простых, но эффективных принципах:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         PatchTST: ДВЕ ИДЕИ                              │
│                                                                         │
│  1. PATCHING (патчинг)                                                  │
│     ──────────────────                                                  │
│     Группировка соседних точек в один токен                            │
│                                                                         │
│     Point-wise:  [x₁][x₂][x₃][x₄][x₅][x₆][x₇][x₈]  → 8 токенов        │
│     Patch-wise:  [x₁ x₂][x₃ x₄][x₅ x₆][x₇ x₈]      → 4 токена         │
│                                                                         │
│  2. CHANNEL INDEPENDENCE (независимость каналов)                        │
│     ──────────────────────────────────────────────                      │
│     Каждый канал обрабатывается отдельно (shared weights)              │
│                                                                         │
│     Channel 1: ───→ [Transformer] ───→ Forecast 1                      │
│     Channel 2: ───→ [Transformer] ───→ Forecast 2  (те же веса)        │
│     Channel N: ───→ [Transformer] ───→ Forecast N                      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Почему патчинг работает

**1. Семантическая значимость токенов**

В предыдущей главе мы обсуждали: одиночная точка временного ряда не несёт семантики. Но патч из 16 точек — это уже **локальный паттерн**: тренд, колебание, пик.

```
Одна точка:    105.3     → Что это значит? Ничего без контекста.

Патч (16 точек):
[100, 102, 105, 108, 112, 115, 118, 120, 122, 123, 124, 125, 125, 124, 123, 122]
     ↑
     Восходящий тренд с выходом на плато и началом снижения
```

Attention между такими патчами имеет смысл: модель сравнивает **паттерны**, а не числа.

**2. Снижение вычислительной сложности**

При длине входа $L$ и размере патча $P$:
- Point-wise: $L$ токенов → Attention $O(L^2)$
- Patch-wise: $\approx L/P$ токенов → Attention $O((L/P)^2)$

При $L=512$ и $P=16$:
- Point-wise: $512^2 = 262,144$ операций
- Patch-wise: $32^2 = 1,024$ операций — в **256 раз меньше**

**3. Более длинный контекст**

Снижение сложности позволяет использовать значительно больший lookback window. Если раньше $L=96$ было практическим пределом, теперь можно подавать $L=512$ или больше, не превышая бюджет памяти.

## Архитектура в деталях

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        АРХИТЕКТУРА PatchTST                             │
│                                                                         │
│  Вход: x ∈ ℝ^(L×C)  (L точек, C каналов)                               │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Channel Independence: обрабатываем каждый канал отдельно       │   │
│  │                                                                  │   │
│  │  Канал c: x_c ∈ ℝ^L                                              │   │
│  │      │                                                           │   │
│  │      ▼                                                           │   │
│  │  ┌──────────────────────────────────────────────────────────┐   │   │
│  │  │  1. PATCHING                                              │   │   │
│  │  │     Разбиваем на патчи размера P со страйдом S           │   │   │
│  │  │     Число патчей: N = ⌊(L - P) / S⌋ + 1                  │   │   │
│  │  │                                                           │   │   │
│  │  │     [x₁...xₚ] [xₛ₊₁...xₛ₊ₚ] ... [xₗ₋ₚ₊₁...xₗ]           │   │   │
│  │  │         ↓          ↓                  ↓                   │   │   │
│  │  │     patch₁      patch₂    ...     patchₙ                 │   │   │
│  │  └──────────────────────────────────────────────────────────┘   │   │
│  │      │                                                           │   │
│  │      ▼                                                           │   │
│  │  ┌──────────────────────────────────────────────────────────┐   │   │
│  │  │  2. PATCH EMBEDDING                                       │   │   │
│  │  │     Linear projection: ℝ^P → ℝ^D                         │   │   │
│  │  │     + Learnable positional encoding                      │   │   │
│  │  └──────────────────────────────────────────────────────────┘   │   │
│  │      │                                                           │   │
│  │      ▼                                                           │   │
│  │  ┌──────────────────────────────────────────────────────────┐   │   │
│  │  │  3. TRANSFORMER ENCODER                                   │   │   │
│  │  │     Multi-head self-attention + FFN                      │   │   │
│  │  │     (стандартный encoder, без decoder)                   │   │   │
│  │  └──────────────────────────────────────────────────────────┘   │   │
│  │      │                                                           │   │
│  │      ▼                                                           │   │
│  │  ┌──────────────────────────────────────────────────────────┐   │   │
│  │  │  4. FLATTEN + LINEAR HEAD                                 │   │   │
│  │  │     Конкатенация выходов → Linear → Прогноз ŷ_c ∈ ℝ^H    │   │   │
│  │  └──────────────────────────────────────────────────────────┘   │   │
│  │                                                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Выход: ŷ ∈ ℝ^(H×C)  (H точек прогноза, C каналов)                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1. Patching

Входной ряд длины $L$ разбивается на патчи размера $P$ с шагом (stride) $S$:

$$\mathbf{x}_p^{(i)} = [x_{(i-1)S + 1}, x_{(i-1)S + 2}, \ldots, x_{(i-1)S + P}]$$

Количество патчей:

$$N = \left\lfloor \frac{L - P}{S} \right\rfloor + 1$$

**Типичные значения:** $P = 16$, $S = 8$ (50% overlap). Overlap позволяет патчам «перекрываться», что сглаживает границы.

### 2. Patch Embedding

Каждый патч проецируется в пространство размерности $D$ через линейный слой:

$$\mathbf{z}^{(i)} = \mathbf{W}_p \mathbf{x}_p^{(i)} + \mathbf{b}_p, \quad \mathbf{W}_p \in \mathbb{R}^{D \times P}$$

К эмбеддингам добавляется **learnable positional encoding**:

$$\mathbf{z}^{(i)} \leftarrow \mathbf{z}^{(i)} + \mathbf{PE}^{(i)}$$

**Почему learnable, а не sinusoidal?** Авторы экспериментировали с обоими вариантами. Learnable PE показывает лучшие результаты на большинстве датасетов, особенно когда сезонность явно не выражена[^patchtst].

### 3. Transformer Encoder

Стандартный encoder с multi-head self-attention и feed-forward network:

$$\mathbf{Z}' = \text{LayerNorm}(\mathbf{Z} + \text{MSA}(\mathbf{Z}))$$
$$\mathbf{Z}'' = \text{LayerNorm}(\mathbf{Z}' + \text{FFN}(\mathbf{Z}'))$$

где MSA — multi-head self-attention, FFN — двухслойный MLP с GELU.

**Ключевое отличие:** Encoder-only архитектура. Нет autoregressive decoder. Весь прогноз генерируется за один forward pass (как в N-BEATS, DLinear).

### 4. Prediction Head

Выходы encoder'а флаттенятся и проецируются в прогноз:

$$\hat{\mathbf{y}} = \mathbf{W}_{\text{head}} \cdot \text{Flatten}(\mathbf{Z}'') + \mathbf{b}_{\text{head}}$$

где $\mathbf{W}_{\text{head}} \in \mathbb{R}^{H \times (N \cdot D)}$.

## Channel Independence: почему это работает

Интуиция подсказывает: модель должна моделировать зависимости между каналами. Температура влияет на потребление энергии, цена влияет на спрос.

Но эксперименты показывают обратное[^patchtst]:

| Подход | ETTh1 MSE | ETTh2 MSE | Weather MSE |
|--------|-----------|-----------|-------------|
| Channel-Dependent | 0.386 | 0.340 | 0.259 |
| **Channel-Independent** | **0.370** | **0.332** | **0.238** |

**Почему channel-independent лучше?**

1. **Меньше параметров.** При $C$ каналах channel-dependent модель имеет attention размера $(C \cdot N) \times (C \cdot N)$. Channel-independent — $N \times N$ с общими весами.

2. **Меньше переобучения.** Корреляции между каналами в train могут не сохраняться в test. Модель «запоминает» ложные зависимости.

3. **Лучшее обобщение.** Shared weights между каналами работают как регуляризация. Модель вынуждена выучить универсальные паттерны.

4. **Data augmentation.** Каждый канал — отдельный пример для модели. При $C$ каналах и $B$ батчей эффективный размер батча — $B \cdot C$.

```
┌─────────────────────────────────────────────────────────────────────────┐
│           CHANNEL-DEPENDENT vs CHANNEL-INDEPENDENT                      │
│                                                                         │
│  Channel-Dependent:                                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  [Ch1 patches] [Ch2 patches] [Ch3 patches] → Transformer →     │   │
│  │                                              (один большой)     │   │
│  │  Attention между ВСЕМИ патчами всех каналов                    │   │
│  │  Размер: (C × N) × (C × N)                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Channel-Independent:                                                   │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  [Ch1 patches] → Transformer ─┐                                │   │
│  │  [Ch2 patches] → Transformer ─┼─→ (shared weights)             │   │
│  │  [Ch3 patches] → Transformer ─┘                                │   │
│  │                                                                 │   │
│  │  Attention только внутри канала: N × N                         │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## Supervised vs Self-Supervised

PatchTST работает в двух режимах:

### Supervised (стандартный)

Модель обучается напрямую на задачу прогнозирования с MSE/MAE loss:

$$\mathcal{L} = \frac{1}{H} \sum_{t=1}^{H} (y_t - \hat{y}_t)^2$$

### Self-Supervised (pre-training)

Вдохновлённый BERT masked language modeling, PatchTST использует **masked patch prediction**:

1. Случайно маскируем часть патчей (обычно 40%)
2. Обучаем модель восстанавливать замаскированные патчи
3. Fine-tune на downstream задачу прогнозирования

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    SELF-SUPERVISED PRE-TRAINING                         │
│                                                                         │
│  Исходные патчи:                                                        │
│  [P₁] [P₂] [P₃] [P₄] [P₅] [P₆] [P₇] [P₈]                               │
│                                                                         │
│  После маскирования (40%):                                              │
│  [P₁] [MASK] [P₃] [MASK] [P₅] [MASK] [P₇] [P₈]                         │
│                                                                         │
│  Задача: восстановить P₂, P₄, P₆                                       │
│                                                                         │
│  Pre-training loss:                                                     │
│  L = MSE(P̂₂, P₂) + MSE(P̂₄, P₄) + MSE(P̂₆, P₆)                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**Результаты self-supervised:** На ETTh1 (горизонт 336) pre-trained PatchTST улучшает MSE на **8%** относительно supervised-only[^patchtst].

Self-supervised особенно полезен, когда:
- Мало размеченных данных для целевой задачи
- Много unlabeled исторических данных
- Transfer learning между доменами

### NeuralForecast

```python

from neuralforecast.models import PatchTST
from neuralforecast.losses.pytorch import MAE

HORIZON = 96

model = PatchTST(
    h=HORIZON,
    input_size=512,           # длинный lookback благодаря патчингу

    # Параметры патчинга

    # Transformer параметры

    # Обучение
```

### Выбор размера патча

Размер патча $P$ — критический гиперпараметр:

```python
def suggest_patch_size(season_length: int, input_size: int) -> int:
    """
    Эвристика для выбора размера патча.

    Принципы:
    1. Патч должен быть меньше периода сезонности
       (иначе один патч = один период, теряем granularity)
    2. Патч должен быть достаточно большим для семантики
       (минимум 8-16 точек)
    3. Число патчей должно быть разумным (16-64)
    """
    # Патч не больше половины сезона
    max_patch = season_length // 2

    # Патч не меньше 8
    min_patch = 8

    # Целевое число патчей: ~32
    target_patches = 32
    suggested = input_size // target_patches

    return max(min_patch, min(max_patch, suggested))

# Примеры
suggest_patch_size(season_length=24, input_size=512)   # → 16 (часовые данные)
suggest_patch_size(season_length=7, input_size=128)    # → 8 (дневные данные)
suggest_patch_size(season_length=12, input_size=96)    # → 8 (месячные данные)
```

## Гиперпараметры

| Параметр | Типичные значения | Комментарий |
|----------|-------------------|-------------|
| `patch_len` | 8, 16, 24 | Больше → меньше токенов, грубее granularity |
| `stride` | patch_len // 2 | 50% overlap обычно оптимален |
| `input_size` | 336, 512, 720 | Можно больше благодаря патчингу |
| `hidden_size` | 64, 128, 256 | Размерность эмбеддингов |
| `n_heads` | 4, 8 | Число attention heads |
| `e_layers` | 2, 3 | Число encoder layers |
| `d_ff` | 2 × hidden_size | Размерность FFN |

**Практические советы:**

1. **Начните с дефолтов:** `patch_len=16`, `stride=8`, `hidden_size=128`
2. **Увеличивайте lookback:** PatchTST хорошо справляется с длинным контекстом
3. **Не переусложняйте:** 2-3 encoder layers обычно достаточно
4. **Self-supervised:** Рассмотрите pre-training, если много исторических данных

## Сильные стороны

**Длинный контекст.** Благодаря патчингу можно использовать $L=512$ и более без взрыва памяти.

**Channel Independence.** Работает как регуляризация, улучшает обобщение.

**Self-supervised pre-training.** Возможность использовать unlabeled данные.

**Ответ на DLinear.** Первая трансформерная модель, убедительно превосходящая простые бейзлайны.

**Простота.** Стандартный Transformer encoder без экзотических модификаций.

## Ограничения

**Channel Independence — не всегда плюс.** Если корреляции между каналами критичны, channel-independent подход их игнорирует. Для таких случаев — iTransformer (глава 22).

**Фиксированный горизонт.** Как и N-BEATS, DLinear — encoder-only модель с фиксированным $H$.

**Выбор patch_len.** Неправильный размер патча может ухудшить результаты. Требуется подбор под данные.

**Не probabilistic.** Базовая версия выдаёт point forecasts. Для uncertainty — нужны модификации.

## Когда выбирать PatchTST

✅ **Используйте PatchTST, если:**
- Важен длинный контекст (lookback > 200)
- Много исторических данных для pre-training
- Работаете с многомерными рядами, где каналы относительно независимы
- Хотите трансформерную модель, но с разумной эффективностью

❌ **Рассмотрите альтернативы, если:**
- Критичны корреляции между каналами → iTransformer
- Нужен probabilistic output → DeepAR, Lag-Llama
- Ограниченные вычислительные ресурсы → DLinear, N-HiTS
- Zero-shot на новых данных → Chronos, TimesFM

## Выводы

1. **Патчинг — ключ к успеху трансформеров** во временных рядах. Группировка соседних точек создаёт семантически значимые токены.

2. **Channel Independence** часто лучше channel-dependent подхода благодаря регуляризации и меньшему переобучению.

3. **PatchTST ответил на критику DLinear:** трансформеры могут работать, если правильно адаптировать архитектуру.

4. **Self-supervised pre-training** открывает возможности для transfer learning во временных рядах.

5. **Практический выбор:** PatchTST — хороший default для задач с длинным контекстом и многомерными данными.

В следующей главе рассмотрим **iTransformer** — модель, которая инвертирует измерения: attention между каналами вместо timesteps.
